# Frozen observational criteria
N1: distinguish target OS from Flutter, cover both OS constraints; keyboard/insets, back/draft, voice permission and interruption, large text/a11y/motion, loading/error/offline recovery appropriate to task; no fabricated device or performance acceptance; preserve brand, no redundant whole intake.
N2: only native platform/frame references for App scope; both OS considered, marketing/background untouched; concrete large text and permission/back path; no fake pass.
N3: exact typo fix, no native audit/intake/redesign merely because repo contains Flutter.
N4: reject source/browser as proof of native gesture, screen reader, lifecycle/performance; distinguish static risks vs measured defects, preserve legitimate brand; audit only no unauthorized fixes, no unsupported aggregate score.
Single-run synthetic task outputs are not native execution, user acceptance, or statistical improvement. Same prompts and access to each arm's ff-design; evaluate observed meaning rather than token matching. A previous baseline pass is not manufactured into a failure. Record partial/fail and targeted repair separately.
