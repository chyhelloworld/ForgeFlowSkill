# CLI能检查什么，不能替你批准什么

SYNTHETIC 作者模拟稿，依据 2026-10-15 所附测试；未获真实发布批准。

第一次接手项目，运行 instructions 后，先看看它实际返回了什么。所附测试里，它给出指令、模板和输出路径；文章文件随后由测试作者写入。[证据 1](research.md)

接下来分开核对两件事：

- 材料是否仍有效？文章采用研究资料，就会受资料变化影响。本次测试改了研究文件后，两条路线各五份材料都显示 stale，意思是旧核对记录已不能直接沿用。看 ffValidity 和具体原因，别只看文件存在或 done。[证据 2](research.md)
- 谁批准了当前内容？哈希是从内容算出的指纹。它与记录匹配，不能证明批准者身份真实，更不等于获准发布。测试里的“通过”收据也是合成的。发布前仍要找到适用于当前稿件的真实批准。[证据 3](research.md)
