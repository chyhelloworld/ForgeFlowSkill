# Independent 0.6 optional methods evaluation

## Scope and evidence classes
- Machine: actual project-local ff-spec launcher, commands/stdout/stderr/exit codes, synthetic files and conspicuously labeled test-only receipts. No receipt authenticates a user or evaluates a model.
- Static: delivered skill/template/route text inspected after implementation freeze; this establishes presence and consistency, not behavior reliability.
- Model simulation: one labeled synthetic-author short blog task, plus targeted branches for alternative structure, changed material, fact conflict and zero-rule retro. Actual resulting text retained. A single instructed run is not a blinded comparison, statistical model benchmark, or proof of production reliability.
- No publish/upload/deploy/merge; frozen 0.5 tree read only. Test projects live under this directory.

## Machine cases
1. Each of research, retro, writing-fragments, writing-shape, writing-beats independently resolves instructions and recognizes manually created output in a one-artifact schema.
2. Separate shape and beats DAGs: neither requires the unselected route.
3. Native new creates change metadata; instructions DOES NOT write the artifact. The agent or user authors it.
4. Five bound artifacts accepted with test-only matching hashes/review version; docs-only skip_specs validates.
5. Research changes after capture; all five go stale transitively, status leaves bytes untouched, archive bypass flags fail.
6. Old review targetVersion rejected; schema contract mutation invalidates receipt.
7. Completed fixture archive keeps article/research attachments out of canonical specs.
8. Canceled and rejected incomplete/stale fixtures preserve original bytes and canonical specs, without manufactured passing receipts.
9. skip_specs with actual spec delta fails; no arbitrary attachment promotion.

## Model scenario
Topic: What a workflow CLI can verify about a draft. Synthetic author is an internal-tools maintainer writing a short practical blog. Observed CLI evidence is genuine; personal anecdotes are explicitly synthetic. Initial tempting but false sentence says instructions creates finished Markdown. Read-only command evidence disproves it. Mid-flow author material retracts a time-savings statistic and changes audience to first-time maintainers. Existing rule already requires technical verification; retro should add zero rules, retain the falsified candidate and explain why. No external quotes or invented citations. Output remains local draft, never publication.

## Explicit limits
Upstream CLI source adaptation stays 1.14.2-ff.0.5.0-rc3 unless implementation changes it; 0.6 labels optional method package, not newly tested upstream CLI code. Generic custom schema support does not imply these schema names are built in. CLI validity cannot determine truth, user consent, author voice, or publication permission. Linux-only test execution.
