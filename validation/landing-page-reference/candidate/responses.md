## L1 · 第一轮：仅章节纲要

页面以帮助 3–10 人设备维护团队负责人判断是否适合、再考虑预约演示为主。沿用海军蓝/白色、Inter 和静态顶部导航，不加动效。

| 顺序 / 章节 | 本节要回答的问题 | 使用的事实与边界 |
| --- | --- | --- |
| 1. 产品与适用团队 | 工单清单是什么，是否适合我的团队，下一步是什么？ | 面向上述团队；主动作是预约演示，但渠道尚未开放，明确标注。 |
| 2. 四项已具备能力 | 日常工单可以怎样登记、分工、查看和导出？ | 只介绍登记工单、指派负责人、按状态筛选、导出 CSV，不添加自动提醒。 |
| 3. 迁移、上手与数据 | 旧 Excel 能直接导入吗，需要培训吗，数据能导出吗？ | Excel 导入尚未实现；培训需求没有验证，不承诺无需培训或立即上手；已支持 CSV 导出。 |
| 4. 演示预约状态 | 现在能预约吗，会不会提交个人信息？ | 渠道未开通；离线原型不收集信息，按钮禁用并说明未开放。 |

不加入客户案例、评价、收益数字、价格、免费试用或退款承诺。待核实的只有培训安排、迁移具体办法及未来预约入口，不妨碍先做边界明确的离线原型。

目前只整理了纲要，没有写正文或 HTML。请确认章节顺序；确认后再按此结构实现。

## L1 · 第二轮：收到案例提供的纲要确认后

整体概念是“先看四项现有能力，再核对使用边界”：首屏说明对象与产品，能力区逐项说明，疑虑区明确 Excel 导入未实现、培训要求未知及 CSV 可导出，最后说明预约暂不可用。不加入客户评价、效果数字或政策承诺。未新增视觉方案审批，沿用已给定规则。

预期主要路径：打开首屏 → 用导航阅读能力 → 查看迁移/培训/导出回答 → 到预约说明获知暂不可预约；导航可以返回对应章节。不存在提交、重复提交、提交失败或成功状态，均不适用，不把离线浏览当成预约成功。

实际完成的是源码自检：页面内锚点均有目标、ID 不重复、两处预约按钮包含 disabled、没有外部资源 URL。已写移动断点与弹性字号，但尚未进行桌面/390px 浏览器渲染、键盘或触摸实测，不能据此宣称可读性验收通过。Inter 采用本机字体优先，离线无字体资产的设备会使用中文后备字体；本原型不下载字体。没有进行独立视觉审查，真人审美接受仍未知；本次案例提供的确认只用于推进该合成试验。

本轮边界：只创建此样例，没有修改产品源码、上线或开放预约。评价：需求理解与交付范围符合输入（文件及静态检查）；设计效果未知（未渲染/无真人反馈）；变化适应不适用（未发生方向变化）；成本仅涉及本地文件生成，无新增依赖或联网，时间/token 未测量。

## L3 · 独立响应

这是后台操作区，不使用官网结构。保留 Inter、蓝白配色和左侧栏，仅说明筛选区：

- **负责人**：单选，默认“全部负责人”；候选沿用现有负责人数据。
- **状态**：单选，默认“全部状态”；选项沿用现有状态名称，不新增业务状态。
- **组合规则**：两个条件取交集，选中后更新列表；筛选控件始终保留当前值。键盘可操作，标签与焦点清晰可见。
- **清空筛选**：将两个条件都恢复为“全部”，显示未筛选列表；不清除工单或其他数据。
- **无结果**：保留筛选区，列表区显示“没有符合当前筛选条件的工单”，提供“清空筛选”；不要误写为系统中没有工单。
- **若读取异步**：更新中显示加载反馈；读取失败显示重试并保留条件，不能把错误当作“无结果”。

以上是最小交互建议，不是既有实现的验证结论；本轮未写代码或改布局。
