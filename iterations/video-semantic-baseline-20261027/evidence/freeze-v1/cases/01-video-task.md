# 视频同题架构推导任务（给推导者）

## 输入性质与边界

这是一份根据一段 Agent 架构教学视频的约 5 秒间隔官方预览帧及可读烧录字幕重构的任务输入，不是原作者的完整原话规格；没有完整音轨或字幕可供验证。已去除视频中的类名、分层数量和目录答案。请只依据以下需求独立推导，不读取参考答案、原视频分析文件或其他候选输出；不得借助原视频链接检索答案。

目标是设计一个能进行多轮对话、调用工具的 Agent 后端，展示从实际工作流程到可实现软件结构的推导。关注模型供应商切换、会话存储替换、工具调用前审查和后续扩展，而不只是写一个能跑的循环。

## 工作流程

1. 开始新对话，或者继续之前的对话。
2. 收到用户消息，将其纳入当前对话。
3. 组织此次调用所需输入，包括指令、历史消息和可用工具说明。
4. 调用模型，获得回答；回答可能包含工具调用请求。
5. 对拟执行的工具调用进行审查。本题的视频示例采用模型参与审查，审查需要相关对话和拟调用内容，产生是否允许以及理由的结论。
6. 根据结论执行工具或拒绝执行，将执行结果或拒绝信息带回对话，供后续模型调用使用。
7. 如仍需工具则继续循环；没有工具调用时结束。本题画面也展示了迭代次数上限，设计需有有限循环出口，但具体上限值未规定。
8. 持久化对话，便于后续继续。

工作流程的顺序用于说明主要行为，不规定唯一的数据结构、函数拆分或存储事务时点。

## 必须考虑的变化与语义

- 模型供应商的请求、响应及参数格式可能不同。切换供应商时不应迫使整个业务流程到处识别供应商格式；本题举例涉及多个供应商，具体 SDK 版本和网络 API 格式未规定。
- 正常回答与工具审查使用不同的指令、输入组织和预期输出；允许采用不同模型配置。如何封装这些职责，由你推导。
- 对话需要可标识、可追加消息、可保存和再次读取，并能列出已有对话。应能区分用户输入、模型回复、工具调用和对应结果，不规定必须一类消息一个类。
- 存储最初可使用本地逐行 JSON 文件，之后可能换成数据库；测试也应能替换实际存储。切换具体存储不应改写对话业务流程。
- 工具需要向模型说明自身名称、用途和参数，并能实际执行调用、返回结果。示例工具能运行 shell 命令；具体命令执行机制未规定。
- 外部入口可以是网页/HTTP，也可由命令行调用；入口变化不应要求重写核心对话流程。本题不要求同时完整实现两种入口。
- 系统启动时需要把所选模型、存储、工具、调用入口及业务过程连接成能运行的整体；具体连接方法由你设计。

## 不得偷偷扩题

- 不把取消任务、费用预算、分布式一致性、并发控制或同步权限系统加入本题强制需求。
- 分叉对话和压缩历史在视频末尾只是扩展练习，不是本轮必须交付的能力；可以解释扩展位置，但不得按其缺失判本题失败。
- 模型审查不等于真实安全边界。不要从视频未展示其他机制，推断系统已具备或必然缺少某种生产级安全保证。若提出额外权限、隔离或确定性策略，请明确它是可选建议或待确认项，不改变本题的必做范围。
- 未规定的异常恢复、重试、事务时机、流式输出、工具并行、人工审批和部署方案，请标记未知或显式写出最小假设，不冒充原始要求。

## 交付

给出一份可理解、可实现的架构推导，不必实现完整程序：

1. 从上述流程逐步说明核心对象/模块为什么需要出现，而非只贴最终结构。
2. 核心对象/模块的职责、关键输入输出、代表性字段和方法或函数契约；可用伪签名，不编造供应商 SDK API。
3. 一张表达主要关系的图，区分必要的调用、拥有/数据关系和依赖关系，避免无法理解的全量细节堆叠。
4. 一条正常对话与工具审查/执行路径，说明各职责如何协作，避免用静态图代替运行过程。
5. 一个与上述职责对应的目录草案，说明启动时如何连接具体实现。
6. 简述模型、存储、入口变化各自影响哪里；注明未知和假设。

评判重点是语义与可追溯推导，不要求猜中视频命名、层数、类数量、语言语法或文件路径。合理的函数式、组合式或其他等价方案均可。
