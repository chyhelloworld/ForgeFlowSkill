# FF 0.11.0 源码候选

工作分支 `work/arch-grower-board-ui`，基线 `b2169a2`（已合入 main 的 0.10.0）。本次只推进版本、同步安装载荷及记录兼容性分析，未实现看板移植，也未改变默认工作流。21 项技能保持不变，两个独立元能力仍按各自版本登记。

## Arch-Grower 与 FF 0.10 的兼容边界

| 借鉴项 | FF 0.10 已有做法 | 0.11 后续试验应守的边界 |
| --- | --- | --- |
| 先做最小闭环，再逐轮完善 | [Plan](../../skills/ff-plan/SKILL.md) 已要求可演示、可验收的纵向切片，[Implement](../../skills/ff-implement/SKILL.md) 已负责按获准计划实现 | 不新增「骨架开发」阶段；只在选用 [Derive](../../skills/ff-architecture-derive/SKILL.md) 时突出本轮主路径和关键依赖。用现有切片和任务记录串到实现，架构骨架不是已运行的闭环。 |
| Fog、折叠、聚焦 | Derive 区分已确认事实、拟议和未知，项目门禁按其适用策略和回执判定 | 折叠是显示方式，不改变范围、依赖或门禁；未知的必需条件必须仍可见且不可报完成。 |
| 图节点导出任务、标 ready | Plan 用现有规格和计划，[DSH 看板](../../dsh-plugin/generate-board.mjs) 从 FF 关联索引与 OpenSpec 的 `tasks.md` 生成只读快照 | 不让节点或影子仓库另立任务进度；同一任务从原记录投影。设计就绪、任务勾选、证据充分、用户验收必须分开显示。 |
| 边试边改 | [Prove](../../skills/ff-prove/SKILL.md) 可做有界验证，[Review](../../skills/ff-review/SKILL.md) 负责独立审查 | 模拟通过只证明对应实验；关键假设或验收变化回到适用的确认和审查，不因看板状态自动放行。 |

建议先在一个实际项目的单条主路径试用：复用 Arch-Grower 看板界面和 MIT 许可声明，继续读取 FF 自己的记录。不引入 `.arch` 状态库、Shadow Git 或第二套审批。用相同材料对照原视图，记录使用者能否更快指出目标偏差并找到证据；另做一个「折叠必需条件后仍显示阻塞」的反例。以上是待验证建议，不是试验通过结论。
