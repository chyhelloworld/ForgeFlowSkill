# 0.9 有界设计：先完整旅程，再核对实际证据

基线：0.8 提交 47eedff1a7c1885ea002a99b97fb1cd0ed157ccd。本文先于本版实现冻结；不把用户四个创意方案转成开发任务。

## 目标与用户价值假说

帮助使用 FF 的执行者先说明访客从入口到成功结果的主要路径、状态转换、返回/失败路径和视觉方向，再逐步对照同一实现版本的实际操作。交付可核查不等于价值已证实；“减少漏测和查找时间”只是尚无基线和真人样本的价值假说。

范围是 ff-design 的增量协议和一个可选只读记录检查器，沿用 17 技能、现行规格和唯一计划。既有原型/设计/实现权限不变；只做设计的请求不改代码。检查器不是执行器、视觉裁判或新的发布门禁。

## 完整业务旅程先于实现

每个主要旅程从实际用户入口写到可观察的成功结果，包含参与者、动作、进入/离开状态、已有需求或规格 ID，以及关键取消/返回/重试路径。多分支按真实业务选主路径和重要反例，不穷举所有页面，也不要求固定阶段数量。设计方向至少说明信息层级、内容/状态反馈、目标视口和影响判断的交互/动效约束；沿用有效方向，存在重大选择时再提供可见候选。

预期是批准规范的引用；观察是当前实现的事实，两者分栏。截图只证明某时刻可见内容；操作轨迹才支持交互转换，二者都不能代替业务结果、设备实测或真人接受。CodeGraph 仅用于技术结构线索。

## 本版真实示范：现有离线手册

选择本仓库已有文档界面，不新建业务应用。访客要在手册找到本版旅程规则，阅读可见说明，遇到空筛选后恢复目录，再在窄屏完成同一任务。期望与基线截图来自真实既有手册；已有浅纸色/深蓝文字/固定桌面目录的 Read 方向保持，窄屏目录回到正文前。无新品牌、3D 场景、动效或图谱平台。

| 稳定步骤 ID | 进入 → 离开状态 | 实际操作与可观察结果 |
| --- | --- | --- |
| open | start → contents | Chrome 打开本地手册，目录和正文可见 |
| filter | contents → filtered | 输入“旅程”，匹配目录可见、无关项隐藏 |
| navigate | filtered → rules | 点击本版规则链接，URL 锚点、稳定滚动后标题/正文对应 |
| empty | rules → empty-filter | 输入无匹配查询，匹配数为 0，正文/锚点未被改写 |
| restore | empty-filter → rules | 清空查询，全部目录恢复，原锚点保留 |
| narrow-open | rules → narrow-contents | 390×844 窄视口重新打开，目录/正文不横向溢出 |
| narrow-filter | narrow-contents → narrow-filtered | 筛选同一规则，得到可操作目标 |
| narrow-navigate | narrow-filtered → narrow-rules | 点击同一目标，稳定后规则可见、无页面脚本错误 |

1440×1000 与 390×844 是 Windows Chrome 视口仿真，不是手机/触控设备验收。理解程度、视觉偏好、真实辅助技术和真人接受不在本轮已验证范围。空匹配提示可作为观察建议，不能因未批准的新 UI 偏好扩大实现。

## 轻量记录与代码设计

单个临时 JSON 引用 design 与 sources 文件的 path/sha256、目标 target、surface(ui/cli)、expected 步骤和 observations；它不是规范或计划数据库。每步有 id/from/to/action。观察另附实际 trace(path/sha256) 和 UI 截图列表；trace 的 target/stepId/from/to/action/ok/observed 绑定实际采集结果。

检查当前目标、依赖字节、稳定 ID、顺序、相邻状态连续性、预期/观察匹配和证据完整性。UI 不能用 screenshot-only 或 CodeGraph JSON 冒充操作轨迹。成功仅标 OBSERVED（声明记录齐全）；缺失、未知、失败、过期或不匹配标 GAPS/INVALID，不给业务正确、设计达标或人类接受背书。

复用同包 ff-handoff 的已加固文件证据检查，避免第二份 Windows 路径规则；安装器保证同包 17 技能可用。单独复制脚本而缺少该依赖时明确 INVALID，不下载或扩大权限。无新增外部库、后台服务或持久状态。

## 六视角与验证安排

目标/价值：解决漏掉步骤或证据类型混淆，价值未量化。职责：ff-design 持有旅程协议，ff-review 继续三类审查。状态/数据：只引用原规范，保留预期/实测区别。架构：局部脚本复用已验证证据检查，不建新平台。安全：只读、当前授权来自人类，不认证记录真实性。交付/运营：先独立反例和真实 Chrome 操作，再同版 CRAP、版本/manifest/payload 一致性与工作分支提交。

验证覆盖主路径、漏步骤/重复/乱序、状态不连续、旧目标/旧源、只有截图、伪 CodeGraph 轨迹、失败/畸形轨迹、CLI 无 UI、原生路径边界复用和只读性。保留失败及修复；没有复杂度或同版覆盖率的脚本标 NOT_MEASURED，不宣称全部通过。无 CI、发布、部署或主分支合并授权。

参考方法只吸收用户已授权的一般原则：最小审查视图、变化/风险摘要、明确请求/证据/假设和用户价值假说。没有复制或改写 Product Manager Skills 的 CC BY-NC-SA 正文，没有导入整套库。
