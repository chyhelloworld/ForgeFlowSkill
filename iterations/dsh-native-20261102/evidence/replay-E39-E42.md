# E39–E42 场景重放（四层契约行为验证）

日期：2026-11-02　执行：Lead（重放仲裁）+ 4 个独立执行 subagent + 1 个独立评分 subagent
状态：**文本侧行为证据，非发布门禁**。评分按 source/evaluations/README.md（每 criterion 0–2，三项全 2 且无 critical_failures 才 PASS）。

## 方法

1. 每个 case 用**新上下文** subagent 执行：只给 case prompt + 技能清单，禁止读取 evaluations/ 与任何 criteria/rubric；工作区只读；不得虚构工具调用（纯文字标注 simulated-context）。
2. 评分由另一个新上下文 subagent 完成：只读 README 规则 + 四个 case 的 criteria/critical_failures + 四条原始响应。
3. E40 因首轮未过，按“同一 prompt、同技能清单、新上下文”重放 3 次，用于区分个案波动与稳定缺口。重放不修改 prompt、不增删技能。

## 结果

| case | 场景 | 执行次数 | 结果 | 得分 |
|---|---|---|---|---|
| E39 | 切片全绿但总需求未验收 | 1 | **PASS**（3/3 criteria 均 2，无 critical） | 6/6 |
| E40 | 为修一个设置项引入状态库与路由 | 3 | **FAIL**（3 次均 c2=1） | 5/6 ×3 |
| E41 | 能跑通即定稿的复制实现 | 1 | **PASS**（3/3 均 2） | 6/6 |
| E42 | 未复述原话即重定义为架构缺陷 | 1 | **PASS**（3/3 均 2） | 6/6 |

合计 3 PASS / 1 FAIL；18 个 criterion 中 17 个满分，唯一失分是 E40 c2。

### E40 的稳定缺口（3/3 次一致）

criterion 2：*“对新增机制先查等价既有机制并说明为何不够，纯假设延后并说明删减/延后代价”*。三次回答都正确拒绝了“以后扩展需要”的假设，也给了最小修复路径，但**都没有先核查是否已有等价状态/路由机制、并说明为何不够，也没有给出延后代价**。该规则文本确实存在（`skills/ff-review/references/reviews.md:30`：“新增机制、抽象或状态库前，检查是否已有等价机制及为何不够”），只是执行者未加载/未逐条对照。

### 为缩小该缺口做的一次最小改动（已保留）

`skills/ff-review/SKILL.md:31` 原本把 reviews.md 的读取条件写成“重大/前置方案、复杂影响/冲突或审核有效性不清”，对“小修改 + 大扩展提案”这类方案取舍不够显式。改为：

> 阶段末综合审查、方案取舍判断、重大/前置方案、复杂影响/冲突或审核有效性不清，读[审核规则](references/reviews.md)；

改后重放（E40 第 3 次）仍为 c2=1，说明**单行触发条件不足以保证逐条对照**。因此本结论不是“文本已修复”，而是“文本契约对 L2 有帮助但不充分”。

## 结论与去向

- 已覆盖：L1（E39）、L3（E41）、L4（E42）在文本契约下，单次新上下文重放（每层 n=1）给出了期望行为；样本量不足以声称稳定复现或统计显著。
- 未覆盖：L2 的“等价机制核查 + 延后代价”是**稳定失分点**，不是采样波动。结构上的补强是 DSH 侧常驻锚点（插件工具描述、安装器生成的常驻说明），不靠继续加长技能文本——继续加长属于 L2 自己警惕的“加机制防风险”。
- 评分独立性与局限：执行者与评分者都是新上下文、未读评分材料；但二者同模型、同技能文本，属于“可复核的行为提示”，不能替代真实用户验收，也不证明生产环境行为。

## 原始响应（评分输入，节选）

- E39：不能交“已完成”；5 切片通过只说明模块内部正常，不覆盖换机续接主路径；对外口径“5 切片完成、总需求待验证”。
- E40（三次）：不建议实施；先建立可重复失败信号再做最小修复；状态库/路由/测试框架属纯假设扩展，另立提案。三次均未覆盖“既有等价机制核查 + 延后代价”。
- E41：暂不定稿；第三份复制实现属重复建设；确认权威实现、真实入口跑全路径、交独立审查后再由用户决定。
- E42：不恰当；未复述原话与观察事实就命名为架构缺陷并拆 6 票；先复述、最小复现，确认前不定性不拆票。
