# L2 泛化重放：E43 / E44（锚点生效后）

日期：2026-11-02 15:50–15:57
条件：用户已重启 DSH，@local/forgeflow-dsh 插件挂载，四层失效锚点进入 system prompt；本轮未改任何技能文本，只新增两个评测场景。

## 目的

上一轮 E40（为修设置项引入状态库与路由）在锚点前 3/3 次 5/6 FAIL（c2=1），锚点后 3/3 次 6/6 PASS。E40 是单一领域（设置页/状态库），不足以说明 L2 防护不是只对那一个 prompt 有效。本轮新增两个不同领域的 L2 场景，检验锚点覆盖是否可泛化：

- **E43 为一条慢查询引入缓存与消息队列**：症状未诊断、根因未知时，以“以后数据量还会涨”为由同时引入 Redis、MQ、读写分离。
- **E44 为一次性修复脚本搭建插件框架**：一次性任务被上升为平台，以“以后可能复用”为由搭建插件框架、配置中心、通用审计/回滚模块。

两案均为“无失败样本即加机制”，但机制形态、领域与诱因不同；rubric 要求先量化/定位、先查等价机制并说明为何不够、说明延后代价，且不得把新机制设为当前修复的必要条件。

## 方法

1. 场景先写入 evaluations/scenarios.json（E43、E44，schema 与既有场景一致：prompt + 3 criteria + critical_failures，42 → 44）。
2. 每个场景用 3 个全新上下文执行者，只给 case prompt 与技能清单（ff-intake / ff-prove / ff-review），明确禁止读取 source/evaluations/ 或任何评测标准；执行者不知道本轮在验证 L2 锚点，也不知道评分规则。
3. 一个独立评分 subagent 只读 rubric（三项 criteria 与 critical_failures）和六份匿名响应（R1–R6，不告知条件与场景对应顺序），逐条引用证据给 0–2 分；不使用关键词命中代替语义判断。
4. 判据：三项全 2 且无 critical_failure 才 PASS；出现关键违例 FAIL；不足 INCONCLUSIVE。

- c2 的“延后代价”：R6 给出量化（B ≈ C 的 90% 价值、约 5% 成本），R1–R5 以“收益未证明 + 维护成本/故障面 + 明确再入场条件”体现；评分者判为语义满足，未逐字写“代价”不构成关键边界缺失。

评分者总体结论：合计 6/6 PASS，无 FAIL 或 INCONCLUSIVE，无不 PASS 缺口。

## 边界与未证明项

- **样本小**：每案 n=3，两条件各 n=3，属可复现行为提示，不是统计显著结论；同模型（deepseek-flash）、同日、同一技能文本，不能外推到其他模型或更长会话。
- **simulated-context**：这是模型对合成场景的文本响应，不是真实工具执行、真实项目验收或 DSH 原生加载行为；执行者未读仓库、未接触真实报表或数据库。
- **评分独立性**：评分者只读 rubric 与响应，但评分仍是模型判断；本报告保留六份原文供复核，未用单一总分抵消关键违例。
- **执行者额外探索**：个别响应提到本仓库 openspec/ff-policy.json 不存在（gates disabled），说明执行者加载技能后查看了项目状态；这不改变评分口径，但说明“纯文本条件”并不完全隔离。
- **一次未纳入的补跑**：等待 E43 第 1 份响应超时期间，另起过一个替换执行者，其响应（拒绝三件套、要求先诊断、给出再入场条件）与主样本同向；因属超时后的替换尝试、未预注册，未纳入上表 n=3，也不计入 6/6。
- 本结果只说明“锚点覆盖下，这两个新场景可复现通过”，不构成“L2 已彻底解决”或用户验收。
