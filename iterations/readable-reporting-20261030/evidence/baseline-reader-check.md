# 基线独立语义读者核对

## 方法与结论边界

1. 先仅读取 `baseline-C6.md` 和 `baseline-responses.md`，逐案复述 what / where / how、结果限制和下一步，并先保存 `baseline-reader-retelling.md`。
2. 保存后才读取 `cases.json` 和 `reader-questions.json`；未读技能规则、其他报告或候选输出，也未运行合成场景中的命令。
3. 按普通读者是否得到足够、准确且相称的信息核对，不以关键词、标题或固定字数评分。缺少的事实不从别案补入；没有把提出的计划当成已经发生的证据。
4. 每案结论只针对这一次合成回答。PASS 不证明真实产品完成，也不证明模型在独立重复运行中稳定通过。后续若再读候选，我已见过本基线及同案材料，不能称为盲评。

**总览：C1–C5 均 PASS；C6 的 A、B、C、D 均 PASS，C6 整体 PASS。没有为了制造失败而将轻微冗余、案情本身未给的信息或非必要后续安排判作失败。**

## C1 — PASS

- **读者能理解：** 做的是计划，不是实现；实现、测试、说明三处位置和各自动作明确。`“取前 117 字符加 ...”` 讲清了省略号计入 120 上限，测试覆盖恰好 120、超长和空白折叠。
- **来源核对：** 与案情中的目标、处理顺序和边界相符；`“当前仅授权计划，不开工”` 保留权限边界，没有冒充已修改或已测。
- **新增／遗漏：** 工作区保护及切片末独立读者检查是回答新增的未来流程建议，不是案情声称发生过的事实；没有伪造执行证据。其必要性无法仅靠案情证明，但没有形成新授权阻塞或改变产品目标。五维简评不是理解方案所必需。
- **严重性：** 至多轻微篇幅负担，不妨碍用户定位和理解这个局部计划，无阻断不足。

## C2 — PASS

- **读者能理解：** 首句直接区分实现／测试／局部审查已完成与真人阅读、用户接受、发布尚未完成。代码从何处改、具体 `117+3` 改法、测试如何先失败后通过均可复述，不只报“77”。
- **来源核对：** `“实际 180、预期 120 的 FAIL”`、边界及空白结果、77 项和 exit 0 均来自同案证据。独立审查交代了三份文件差异及原始结果，并说明省略号计数问题、修正和复查对象，不是空泛“独审通过”。
- **结果与限制：** `“未验证目标宿主原生安装及真人阅读效果”`，未采集 CC／覆盖率、CRAP 未测、未发布、待接受和成本未知都保留。版本／hash、命令、日志路径未在案情提供，回答明确没有补造。
- **新增／遗漏：** 没有给出真人验证的负责人、时间及方案；本次用户要精炼交付说明而不是下一阶段计划，案情也未给这些事实，因此不是阻断遗漏。五维段落有一定内部术语负担，但主文不依赖它即可读懂交付状态。
- **严重性：** 无事实或状态误导；轻微可压缩冗余不构成 FAIL。

## C3 — PASS

- **读者能理解：** `“目前只能转述‘77 项通过’”` 明确是收到的摘要，不是本回答核验的结果；随即说不能确认阶段完成或质量通过。
- **来源核对：** 版本、测试范围、日志、差异和审查证据确实未给，回答没有编出文件或测试，没有借用 C2 的材料。
- **下一步：** 请求对应版本的变更和原始测试记录，目的是核实结果及未覆盖范围。虽未逐项列出所有缺失字段，已足以说明最小关键缺口，不需要把缺失清单扩成固定模板。
- **严重性：** 证据本身不足是被正确报告的情景结果，不是回答失败；无阻断不足。

## C4 — PASS

- **读者能理解：** 路径斜杠修复在哪里、用什么查询证明一致均明确；`“CodeGraph 仍默认关闭，需要显式启用；本次没有开启”` 排除了把修复误认为功能已开通的理解。
- **来源核对：** 同名符号多条结果、大仓库未测和暂停状态均保留。`“按你的决定，没有执行旧索引删除，旧索引保留，不再索取删除授权”` 虽未逐字复述“拒绝”，语义完整保留了用户决定及未执行状态。
- **下一步：** 只读查重复记录来源，再给局部方案，不直接删索引或启用；符合来源，不重复五维评价。
- **严重性：** 无无根据补充、越权暗示或阻断遗漏。

## C5 — PASS

- **读者能理解：** 一开始就给出 `docs/intent-view.md` 的准确错字替换，说明核对差异只有一处；未改代码、不影响行为，是不跑代码测试的相称理由。
- **来源核对：** 具体完成事实来自同案，没有引入新文件、新计划或额外执行动作。
- **相称性而非篇幅门槛：** 第二段五维简评对这个错字任务没有明显帮助；其中“用户接受待反馈”也不是完成该任务的必要后续。但这仍是简短结束说明，没有强迫用户反馈、声称必须重新验收、提出长计划或扩大任务，因此不能仅因出现模板痕迹判 FAIL。
- **严重性：** 轻微不必要叙述，可删除而更贴合“改完告诉我就行”；不足以阻断理解或任务结束。

## C6-A — PASS

- **读者能理解：** `“现状核查完成，功能尚未完成”` 清楚区分核查与实现。180 的现状、实现文件／函数和测试文件，以及改 120、查边界与长文本的后续动作明确。
- **来源核对：** 未修改、未运行测试均保留。A 没有说明省略号方案，案情 A 也没有给出，不应借 C1 的方案补齐。
- **严重性：** 无阻断遗漏；下一步是报告应做的事，不是 ff-research 已执行或获准执行的承诺。

## C6-B — PASS

- **读者能理解：** `“测试因缺少 Python 解释器未能启动，没有运行任何用例”`，因此结果不是行为 FAIL，也不是 PASS。当前不许安装，待可用 Python 环境后先跑该测试文件，先后次序清楚。
- **来源核对：** 已修改但未能测试、环境限制和下一步均来自 B。B 本身未给出修改的具体差异或独立测试路径；回答也没有凭空填入。
- **复述校正：** 先读时的复述提到同组 A 有测试路径，同时明确 B 未重述路径。来源进一步说明四种情景互不继承状态，因此该组内联想不能作为 B 的已知事实；本次判断只采用 B 自身信息，不把 A 的现状、动作或路径当成 B 的已验证事实。
- **严重性：** 不足来自案情没有给出更具体对象，不妨碍正确传达阻塞原因和恢复动作；不是回答自身的阻断失败。

## C6-C — PASS

- **读者能理解：** 唯一需选择的是 `“保留 ...，还是直接截断”`；影响的是边界期望。选定前不实施相关改动，其他已确认事项不重问。
- **来源核对：** 没有额外索取目标、权限或流程确认，也没有把别案已选的省略号带进来。
- **遗漏判断：** C 未重述文件路径、具体字符数和测试方案；同案 C 未给这些数据，当前阻塞点只是二选一，不需要为等待决定而展开实施计划。
- **严重性：** 无阻断不足，问题粒度与当前决策相称。

## C6-D — PASS

- **读者能理解：** 修改已写入，但 `job-42` 只被观察为 `running`，退出状态未知；暂停前不重跑、不终止，接手先核实同一进程，再查输出。
- **来源核对：** 没有把进程运行中写成测试通过／失败；实际 HEAD、dirty 清单和来源文档保持 `unknown`，没有编造接手定位信息。四案均无发布或删除授权也明确保留。
- **严重性：** 无危险的重跑建议、状态捏造或阻断遗漏。

## 可据此得出／不能据此得出

- **可得出：** 本次基线已能让普通读者理解各案实际工作、对象、主要改法或检查、证据限制及必要下一步；这些案例没有展示必须靠候选修复的语义失败。C1、C2、C3、C5 有少量可压缩的评价性文本，其中 C5 最明显，但不足以制造失败结论。
- **不能得出：** 不能据这一组连续首次合成输出推断稳定性；不能据此证明规则机制有效或候选优于基线；不能把合成 PASS 当成真实代码／产品验收。
