# FF 0.10.0：目标进度与有效推进

批准来源：用户2026-11-12确认按《pstack全功能审阅与FF借鉴方案》v1.2推进，在云端完成，版本推进到0.10。
基线：工作分支 work/resource-lifecycle-20261111，7637116。不是主分支发布。

## 本轮交付
- 在既有 status 入口与 checkpoint/Goal bridge 上增加只读目标进度；已有任务/回执仍为事实来源。
- 用同一记录按配置计算停滞/低进度复盘建议；不是定时器、进程监控或自动原生Goal写入。
- 将选取的调用链、影响面证据、caller-first、可重复项目验证、测量可信度与确定性改进方法融入已有技能。
- 保留轻任务路径；不增加技能数、独立隔夜模式、多模型面板、自动合并或全局清理。
- 封包、静态/行为逻辑/分发回归与独立审查；真实宿主不可用单列。

## 架构复核
- 产品流程：扩展只读查询，停滞后沿用retro。无需新模式。
- 职责依赖：CLI只投影记录和判定建议；宿主负责实际观测，用户授权仍由宿主管理。
- 数据状态：复用现有checkpoint及完成回执，附可选进度观测；不建立第二任务库。
- 权限可靠性：查询不构建、不修改文件、不执行项目命令。未知副作用先核实，不依据旧记录重试。
- 工程排障：固定时钟及边界数据测试；静态分发、独立读者与真实宿主分开报告。
- 版本运营：可选字段向后兼容，旧数据明确unknown；0.10.0为源码候选，不自动升级其他项目。

候选比较：复用现有status和resume足够；局部增加投影和复盘计算；不新建服务/数据库。共享指引只同步到相关独立安装入口，借测试防漂移。

## 验收
查询无副作用；任务勾选不算已证；旧证据/修订不符不自动完成；运行状态不可查为未知；审批等待/暂停/长构建不误触发；状态更新时间不重置有效进展；同前提失败及低进度能触发；结束/取消不自动续跑。工程方法必须给具体证据，P2保持按需而非默认实现。
