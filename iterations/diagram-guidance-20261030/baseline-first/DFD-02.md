# 报销申请系统数据流说明

图中矩形为外部实体，圆角为处理，双竖线形为数据存储；所有箭头表示具名数据，不表示先后执行或审批控制。上下文的系统边界不显示内部存储。未增加外部参与方。

## 上下文图
```mermaid
flowchart LR
 E[员工] -->|申请资料| S(报销申请系统)
 S -->|受理结果| E
 S -->|待审资料| R[审核员]
 R -->|审核意见| S
 S -->|付款指令| F[财务系统]
 F -->|付款回执| S
```

## 一级数据流图
```mermaid
flowchart LR
 E[员工] -->|申请资料| P1(1 处理申请)
 P1 -->|受理结果| E
 P1 -->|待审资料| R[审核员]
 R -->|审核意见| P1
 D1[(D1 申请库)] -->|申请记录| P1
 P1 -->|申请资料及审核结果| D1
 P1 -->|已批准付款资料| P2(2 执行付款)
 P2 -->|付款指令| F[财务系统]
 F -->|付款回执| P2
 P2 -->|付款记录| D2[(D2 付款记录库)]
```

上述存储以 Mermaid 圆柱替代传统开口存储框，仅是绘图工具替代，不改变 DFD 语义。没有实体直连存储、存储互连，也没有把财务回执直接回写申请库，因为需求未授权该数据流。

## “1 处理申请”的分解
子处理编号不表示时间顺序。这里的“整合”表示处理输入数据形成输出，不是审批步骤按钮。

```mermaid
flowchart LR
 E[员工] -->|申请资料| P11(1.1 整理申请资料)
 D1[(D1 申请库)] -->|申请记录| P11
 P11 -->|申请资料| D1
 P11 -->|可审申请资料| P12(1.2 整合审核资料)
 P12 -->|待审资料| R[审核员]
 R -->|审核意见| P12
 P12 -->|审核结果| D1
 P12 -->|受理反馈资料| P13(1.3 形成受理结果)
 P11 -->|资料接收结果| P13
 P13 -->|受理结果| E
 P12 -->|已批准付款资料| P2[2 执行付款：本分解边界外]
```

## 父子平衡与数据含义
|1 的边界流|子图对应|
|---|---|
|员工→申请资料|员工→1.1，名称及内容保持|
|审核员→审核意见|审核员→1.2|
|申请库→申请记录|申请库→1.1|
|1→受理结果→员工|1.3→员工|
|1→待审资料→审核员|1.2→审核员|
|1→申请资料及审核结果→申请库|1.1 写申请资料 + 1.2 写审核结果，聚合等价|
|1→已批准付款资料→2|1.2→2|

申请资料包含初次提交及补充材料，但补充的匹配标识、必填项待确认。审核意见可包含批准、驳回、需补充及原因；受理结果承载相应反馈，不把这些动作另画成控制流箭头。已批准付款资料必须足以生成付款指令，字段及审批有效性规则待确认。付款回执与付款记录的字段、重复回执处理、失败重试规则未确定，本稿不补造。

验收：逐一追踪六条外部流在上下文和一级图均有对应；1 的七类边界流在子图保持，子图不新增财务接口。业务讨论须确认受理结果是否覆盖审核后的驳回/补充通知；若不覆盖，先修正父图数据接口再分解，不能只在子图偷偷加新流。
