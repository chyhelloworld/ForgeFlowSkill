# FF 图法行为验收（冻结 v3-domestic-practice）

这是 **6 个合成业务请求**，用于对照原技能与图法集成候选。未执行模型测试，也未修改技能或仓库实现。

用户最终要求为“参考国内的软件工程或者架构师的要求，画图要单独的 skill”。未执行的 v1/v2 已被本版替代；基准与候选必须使用本版，不能与旧输入混比。每案 model_prompt 均已内置相同国内工程实践前缀，不强制每案国标审计。

## 输入与评审隔离
- `diagram-eval-cases.json` 的 `model_prompt` 是唯一的每案生成请求；不得将 `judge_rubric`、本说明或预拟答案提供给被测模型。
- rubric 是独立评审材料，不是模型输出模板。没有预写标准答案；图法、表达形式及合理分层均可变化。
- 基准与候选逐案使用相同 prompt 原文、相同工具权限、模型与采样配置；基准用原有适用入口，候选用新增独立 ff-diagram skill。此为新增能力对照，非完全相同入口的单变量实验，不能区分图法内容、路由和上下文变化各自的贡献。记录技能版本/哈希、模型版本、实际输入哈希与工具条件；否则不得把差异全归因于技能。
- 开新上下文逐案生成，避免跨案泄露。以匿名 A/B 标识评审，在相同标准下逐项引用输出证据。

## 判定方法
- 每案 5 项独立行为标准，逐项 `pass / fail / not_observable` 并记录证据与理由。语义、边界与可理解性优先，不做关键字命中计分。
- `not_observable` 不算通过；区分输出未交付、渲染不可读与评审材料缺失。不自行替模型补全关键约束。
- 图中的可读结构和邻近文字共同构成证据；文字已说明的机制无需强行加边。ARCH-01 允许简图+约束文字，SIMPLE-06 是明确正常对照，检验是否因图少而误报。
- 核实箭头/关系的实际含义，允许不同规范表示、合法的数据合并拆分和明确的未知标记，不要求固定术语、布局或节点数量。
- 每案全部 5 项通过才算该案通过。报告每项与每案结果，不用总分掩盖错误；基准已通过项在候选中失败即回归。
- 候选小范围验收目标为 6 案全部通过且无对照回归；若基准也全过，只能报告本组未发现差异，不能声称集成带来已证实提升。
- 若模型输出不稳定，在锁定配置下做成对重复并逐次报告；不得只挑最佳候选/最差基准。

## 国内标准核查
- 每案第五项审查图法用途一致性及实际提出的标准主张（不要求每份回答给出编号）；不预置 OMG、C4 或任何国内标准的标准答案。国际方法不是天然禁用，但不得被伪装为国内标准或无说明地替代国内要求。
- 对模型实际引用的标准名称/编号、适用范围、版本及废止替代状态，由评审者另行查权威来源；关键条款主张需有正文证据。验证不到则标注未决，而非凭熟悉程度通过。
- 明确核实限制且不给未经证实的合规承诺，可通过该行为项；这不代表标准事实已完整验证，应单独记录规范证据覆盖率。

## 冻结与边界
冻结内容由 `diagram-eval-cases.sha256` 覆盖 JSON 与此 README；执行前验证哈希。修改题目或 rubric 应另立版本，不覆盖已运行版本。冻结时间为设计开始时点，不代表测试已执行。

这是一组回归烟测，不覆盖所有 UML 图、全部 DFD 记法、物理数据库设计、大图渲染、可编辑 draw.io 文件验证或所有领域架构。它可发现图法混淆、分解不守恒、猜测基数、异常边界失真及过度制图，不能替代规范出处审查与真实项目验收。
