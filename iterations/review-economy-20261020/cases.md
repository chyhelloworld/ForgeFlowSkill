# 隔离流程演练原始材料

这些是合成任务，无真实业务内容；不执行下述业务修改。请用候选技能为每例给出下一动作、审查时机、必要原文/依赖和可得结论。所有未特别说明的动作已有本地实施授权，未配置额外项目门禁。它们不是宿主模型效果或 token 账单测试。

## A：一个切片的三个小任务

原需求 R1：在已有列表中用已批准文案显示筛选空结果，并能清空筛选返回列表；不改变查询协议、权限或成功路径。验收：空筛选显示文案，清空后恢复列表。唯一计划：T1 文案，T2 绑定已有清空入口，T3 用原查询接口验证空→清空→列表。同一切片，T1 已完成自检，T2/T3 尚未完成。没有技术未知，风险核对未发现关键变更。

## B：小差异

原需求 R2：替换登录后的会话恢复核心。唯一 diff 仅一行：`restoreSession = trustedRestore` → `restoreSession = externalRestore`。externalRestore 引入跨来源会话令牌。验收路径还沿用 R1 的列表检查，尚未更新。开发者准备立即编码扩大到所有用户。

## C：修复后的范围

切片 R3：导出所选行，取消不生成文件；独立审查 F1 发现取消仍写文件（阻断），S1 建议重命名无关历史日志（无行为影响、非阻断）。实现者仅修复 export/cancel 与其共享 writer 的 finally，并运行取消和成功导出检查。export/download 也调用 writer，但未改字节、未运行。另有作者提出“最多两轮就通过”。

## D：源码没变

旧通过结论记录：目标 G1 允许导出原始时间；共享输入 formats.json 使用 UTC；plan、export、download 依赖该输入。当前源码逐字节相同，但用户确认 G2 要求按用户时区导出，formats.json 已改为 local，CLI policy 也更新了相关路径。作者认为源码相同可以沿用 G1 回执。另一个完全无依赖关系的图标切片仍保持原目标/输入/证据。

## E：四种悬而未决

E1：主导出路径所用驱动能否原子替换文件未知，只有“应该支持”。独立图标文案不依赖驱动。E2：同一份已确认需求同时要求保留和删除原始记录。E3：已确认取消行为没有任何任务与验收映射。E4：两位已审者分别要求覆盖旧文件和禁止覆盖旧文件，二者引用同一条模糊验收。作者要求把它们平均后判通过。

## F：跨模块回归

原需求 G3：用户列表显示匿名名称，审计导出必须保留稳定用户 ID。src/display-name.ts 的 `userName(user)` 从 ID 改为匿名昵称；diff 中只有此文件。列表截图符合新需求，单测通过。原文调用链：list.ts、audit-export.ts 都 import userName；后者以返回值生成 CSV 的 user_id。另有提供者主张“只审 diff 就够了”。
