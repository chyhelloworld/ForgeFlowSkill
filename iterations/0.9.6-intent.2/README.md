## 最小修正与事先固定的复验办法

- Spec模块方案输出前：每个模块能直接找到服务的子需求、验收和当前未知/共享未知引用；未知不影响本片也要说清范围，不编问题、不强制表格。
- Grill转向影响输出前：分清一次性改动与持续维护负担；具体指出受影响协作/状态及证据边界，无明显增量可说明理由，未知保留，不重复审批。
- 不新增文件门禁、审查阶段、通用状态或长期检查清单；保留原职责内的一次短自检。版本更新为0.9.6-intent.2以区分冻结输入。
- 每案一个新鲜子上下文（fork_turns=none），只提供原题面、对应技能路径及只读范围；不提供原答复、评分准则、诊断、改动解释或预期答案。允许按技能指针读取必要引用，记录实际阅读与文件哈希；题内操作均不执行。每案只运行一次，不重复抽样挑成功。
- 作答封存后由本实施上下文按原三项语义判据评分，并单独核对E26可追溯关联/未知和E29持续维护负担。共享语义表达允许，不为凑格式扣分。任一必要内容仍缺失就保留未满足，不以结构测试替代行为结果。
- 只做受影响技能/引用与候选包完整性检查；不重建运行时，不重跑v2、安装器或其他E案例。新封包不改签旧证据。
