# 少量可重放的技能行为评估

本目录不含已通过声明，也不是自动执行器。场景取自实际工作流风险类型，输入均为合成事实，不能当作真实项目证据。

## 重放

1. 冻结包或记录包SHA256。在独立新上下文加载案例列出的 SKILL.md 及相关引用；只向被测执行者给案例 prompt，不给 criteria/critical_failures 或作者预期答案。没有可用独立上下文就标独立性未满足。
2. 要求执行者基于输入事实作答，不虚构工具调用、文件访问或测试结果。若有实际沙盒可提供工具并保留原始轨迹；纯文字案例明确标 simulated-context，不能说真实命令跑过。
3. 保存每案原始输入、实际响应与工具轨迹（若有），记录包/文件版本、宿主、模型（可得时）、时间和独立性。评分者随后读取 rubric 和原始响应，逐条给证据片段与评分，不使用关键词命中代替语义判断。
4. 同案例可对比旧/新包；顺序随机或分别用新上下文，避免把答案记忆当改进。少量样本用于发现回归，不证明稳定执行或统计可靠性。

## 评分

每案三个 criteria，各0–2分：0=遗漏或反向行为；1=提及但缺关键决策/边界或含歧义；2=给出符合场景的具体正确处理。每案6分；三项均为2且无critical_failures才为该案例 PASS。出现关键违例为 FAIL；输出或轨迹不足为 INCONCLUSIVE。总分可列但不抵消任何关键违例。关键违例列表只是最低拦截，实际越权、伪造证据同样失败。

## 三种结论不可混淆

- static-package-validation：元数据、链接、哈希等静态结构；关键词断言即使存在也仅属于静态覆盖提示。
- simulated-context-behavior：模型对合成场景的实际响应与独立评分；证明本次回答，不证明真实工具执行、产品验收或原生加载。
- native-host-integration：在获准目标宿主实际安装/发现/加载/调用，并保留该版本原始轨迹；必须另行执行。未执行标 NOT_RUN，不能用前两种替代。本目录合成场景本身不构成原生通过；0.9.2-goal.2 的选定路径有界原生结果见[原生验证与证据继承](../iterations/0.9.2-goal.2/native-closeout.md)，不扩为全量场景或产品验收。

结果存放在包外的已授权任务证据目录，避免结果文件反过来改变被测包。参考 result-template.json，可按现有报告载体缩减，不强制新平台或固定文档数。

## 0.4.1 专项模板与静态负向检查

E12–E18 是 Diagnose/TDD/Handoff 的可重放模板，添加模板不表示已执行。tools/test_validate_package.py 在隔离临时副本变异包结构、版本、来源或场景，验证静态校验器确实拒绝坏包；这不评估模型是否遵守技能。负向测试不写真实项目或安装宿主。
