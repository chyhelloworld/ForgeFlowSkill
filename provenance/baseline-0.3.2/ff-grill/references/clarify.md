# 澄清与推荐前自审

源自 FF-Grill v1.3；按当前需要读取，不要求完整流水线。

## 2. AI Self-Grill

每道澄清问题所附的推荐答案，也必须先完成 Self-Grill，不能只审最终方案。逐一检查目标对齐、事实与假设、可行替代、复杂度与代价、证据及可验证性，再向用户展示推荐。按风险选择自审深度，不机械输出长篇检查表；只展示短推荐理由和关键代价，不输出私有思维链。

自审不能替代外部查证。依据不足时标明“暂定推荐”及其条件，或明确“暂不推荐”；继续完成可自行查证的部分，并给出最小验证路径，不把全部判断工作推给用户，不声称自审已证明方案有效。

- **Problem Check**：用户描述的是问题还是方案？若是方案，核实其要解决的问题；不要默认方案错误或重新定义用户意图。
- **Goal Check**：当前需求或方案如何帮助已确认目标？没有明确联系时标记 Goal Drift Risk，说明疑点。
- **Alternative Check**：是否能用更简单方式达成目标？按需考虑不做、删除、延迟或替代；没有实质选择时不强凑方案。
- **Complexity Check**：当前价值能否覆盖开发、迁移与长期维护成本？是否仅因“以后可能需要”提前设计？
- **Evidence Check**：以主要业务流程的可观察结果验证有效，不追求函数/字段/异常穷举或测试数量；实质风险才补少量高价值专项。什么结果能验证有效，如何取得证据？无法验证时标记 Evidence Risk，并提出最小可行验证办法。

## 3. Goal Anchor：先对齐，再决策

从现有上下文提炼问题、现状、期望变化、动机和失败条件。只问仍缺失且会改变决策的信息。

重要讨论以 Goal 为锚点：为什么做、为谁做、成功标准、非目标和约束。复用用户明确陈述或此前确认的信息；AI 提炼或补充的内容先标“待确认”，经用户确认才标“已确认”。

重要需求或设计须说明如何帮助当前目标。发现冲突时说明影响，不自行换目标；修改已确认目标、范围、预算或关键约束须经用户确认。

若需要书面整理，可使用以下人读模板；简单主题用短句即可：

```yaml
Intent:
  problem: null
  current_state: null
  desired_state: null
  motivation: null
  failure: null
Goal:
  why: null
  who: null
  success: null
  non_goal: []
  constraints: []
  status: pending_confirmation
  confirmation: null
```

## 4. Decision Frontier：先查事实，按依赖提问

把关键决策及其依赖关系理清即可，无需强制画图或生成完整树。

1. **先查事实。** 优先读取已授权的代码、文档、配置和证据；能自行查到的不问用户。查不到时说明限制或缺口，再问最小必要问题，不把猜测写成事实。
2. **区分事实与选择。** 事实靠查证；目标、偏好和重要取舍由用户决定。查证未完成时，仅暂停依赖它的问题，继续其他独立问题。
3. **优先处理重要未知。** 通常先看影响目标的问题，再看架构、成本与实施细节；按实际风险调整。与当前决策无关的分支可暂缓。
4. **按依赖分轮。** 同轮提出最重要、前置已满足且彼此独立的问题，不机械一次一问，也不列几十题。依赖本轮答案的问题留到下一轮，回答后更新依赖和待问项。
5. **每题给经自审的推荐和依据。** 按 Self-Grill 先审推荐答案，再编号附上推荐或暂不推荐状态、短理由和关键代价。偏好未知时给条件式推荐并留给用户决定，不捏造偏好；依据不足时标暂定或暂不推荐，并继续查证或给出验证路径。
6. **确认回答范围。** 仅把实际回答记为已确认。笼统的“可以”不能覆盖未明确列出的重大决策、改目标或执行许可；关键范围不清时简短确认。

可用的提问形式：

> Q1：本轮需要决定什么？
> 推荐（必要时标暂定或暂不推荐）：……；理由：……；主要代价：……。

不要为了套格式给每个问题增加无意义的选项；用户可提出推荐之外的答案。

## 5. Design Challenge 与 Complexity Review

按重要性合并评审，无需先后各做一遍。对重大方案明确：

- 为什么需要，服务哪个已确认 Goal？
- 最简单的可行做法是什么？删掉或推迟后，目标是否仍能达成？
- 主要替代方案、收益、风险及开发和维护成本是什么？
- 如何验证，哪些结果会推翻当前判断？

遇到平台化、插件系统、微服务、权限系统、通用框架或自动化平台时，重点检查当前需求和维护负担；保留必要能力，对缺少当前依据的复杂度建议删减或延后，并说明代价。

对高不确定性、可逆的选择，优先推荐范围有限的验证或试验；把假设与验证标准说清楚，不将试验建议当作已授权执行。

## 6. Decision Lock：暂时收敛，可重开

核心问题与目标已确认、关键约束明确、重要未知已解决或其风险获用户明确接受、下一步及验证方式清楚时，停止扩展问题，不为穷尽无关分支延长讨论。

提交与风险相称的结论：Goal、推荐 Decision、理由与取舍、风险和未决项、下一步、review_trigger。已确认部分无需重问；新提炼的 Goal 与待选 Decision 须经确认后才标“已确认”，再在授权范围内执行。

Decision Lock 是可重开的共同决策快照。保留 review_trigger，如假设失效、新证据、成本超界或目标变化；触发时说明并建议重开，不由 AI 自动定案或改写已确认决策。

用户要求先停时，给出已有结论及未决项，不逼问或标为已确认。按所选模式输出；Mode 0 不另存文件。
