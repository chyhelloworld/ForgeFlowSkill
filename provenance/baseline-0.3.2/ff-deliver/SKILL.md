# FF-Deliver 0.3.2-rc1

让获准变化真正交付，技术完成与用户接受分开。引用唯一需求锚点的用户原话、已确认目标/约束/成功标准与待证假设；验收既看新增功能，也看原核心目标和受影响的跨模块约束。可只做当前需要的实现、审查或交接；已有明确计划不重复 Grill，也不强制先做 Prove。

## 锚定本轮

读取最新确认目标/来源、本轮范围和限制、唯一实施计划（可来自 ff-plan 或内联短计划）、相关项目说明/词表、现有命令及当前工作区。按真实依赖选择获准且可开始的切片；不要重建第二份计划。尊重他人未提交修改。事实未知先查，用户取舍未知才问。仅授权规格/原型不能顺带实现。

准备暂停、半成品接手或暂停后恢复时，先读 [接手、恢复与变更](references/continuity.md)，暂停只留短检查点，不追加产品工作；接手/恢复完成状态对账再选剩余切片。依赖验收能力的大规模实施前，先按 [证据与回归](references/evidence.md) 做最小可行性预检，不能拖到交付末尾才发现真实入口不可用。

用户明确采纳变化时，按 [接手、恢复与变更](references/continuity.md) 的短链更新受影响实现、规格与验证；保留旧→新及确认出处，避免用旧标准判新方案。仅讨论的想法不自动加入，也不一律拒绝真实获准变化。超出目标、预算、权限或重要约束的部分暂停并提出具体决定；范围内日常步骤无需重复确认。

## 做与证

- 实现、修复、增加检查时读 [证据与回归](references/evidence.md)。从公开行为切片推进；实际红灯、扫描对象及版本是证据，日志名和退出0不是质量保证。
- 审查或准备交付时读 [三类审核与交接](references/review-handoff.md)。主流程/核心需求、代码规范、计划各有独立结论和证据；按时机复用已有审核，默认独立子代理/新上下文只读审查；任何一类都不能代替另外两类，自检不等于独立通过。
- UI 切片读取已选可见目标与短规则；对照最终实际渲染并操作主要路径。视觉偏差不能由函数测试全绿抵消，真实用户接受不能用模型模拟替代。用户未选方向且未授权自主选择时，不擅自大改全站。
- 验证目标平台和用户真正使用的运行入口，按 [证据与回归](references/evidence.md) 标明实机与跨平台边界。
- 视觉方向失效时只重开相关选择，可用已安装 ff-design；交互/技术假设失效可用 ff-prove，缺用户目标则回澄清。无需造新的 Harness、常驻协调器或固定票数/测试数量。

## 对用户与接手者

切片或阶段交付时，按 [三类审核与交接](references/review-handoff.md) 给简短验收交付面：原始需求、明确版本的运行入口与操作、实际结果/偏差、未证项及需要用户决定的事项（没有则说明）。不靠AI自评宣布没有跑偏，不强制新模板或大量文档；简单改动可短答，严重要点不为凑行数省略。

同一任务复用已有计划和证据位置，先重读再改，保留用户修改。遵守记录选择：Mode 0 不额外保存讨论；开发产物/测试日志按任务自身授权保存，不能借此记完整会话。用户要求停止时仅总结当前状态和缺口，不再扩大或追改产品。工作分支提交、合并、部署、付费、持久权限各依实际授权，技能不新增许可。
