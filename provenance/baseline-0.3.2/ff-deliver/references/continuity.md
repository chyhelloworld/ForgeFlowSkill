# 接手、恢复与变更的最短对账

## 接手半成品

先读唯一需求锚点与计划，核对最新确认目标、权限、实际版本及工作区，包括未提交和未跟踪内容。沿主流程看已有功能；交接声称完成不等于已证，占位 UI、mock、固定响应、未接入调用者与既有失败须明确标出。按当前证据区分已证完成、待复验、部分完成、未开始和受阻，修正唯一计划，只推进剩余或受影响切片。保留他人修改，不能 reset、覆盖或把历史失败归功/归咎于本轮。已有明确目标不重新启动全套澄清与原型。

## 暂停与恢复

暂停时在已有获准载体留短检查点：版本/工作区、已证结果、未完命令的可观察标识和状态、部分产物、未决决定、下一可做片及停止边界；Mode 0 可只在当前对话交接。不要为记录方便保存凭据或完整私人会话。

恢复时先比较目标与权限、文件与环境的变化，再核实旧命令和部分产物。只使用当前宿主可观察的实际状态；无法查询就标未知，不因时间经过推断运行或结束，不启动可能重复写入的同一操作，也不结束他人进程。需要处理确属本任务的进程时仍遵循实际权限和项目约定。独立、不依赖未知结果的获准工作可继续。

给仍有效/因何失效的证据和用户接受分别对账；复用可信证据，对改动范围做最小复验。更新同一计划与下一可做片。明确未决项究竟是可查事实、用户决定还是权限阻塞，只问必须由用户决定的部分。此文件是执行指引，不是后台服务；不承诺自动唤醒、进程存活或强制执行保证。

## 采纳变化的短链

讨论与正式采纳分开。对真实采纳的变化，保留确认来源，追踪：
1. 受影响目标、生产者/调用者/输出，以及已完和未完切片。
2. 哪些测试、审核、演示证据和既有用户接受不再覆盖新版本或新范围，为什么；无关结果继续保留。
3. 最小修订与复验入口，更新唯一计划的验收和依赖；整体约束确受影响时才扩大回归。
4. 哪些不受影响的获准部分可继续，以及尚待用户选择的事项。

可用一小段或原计划条目承载，不造新事实库。新版本不自动继承旧接受；也不把变化理解为所有工作重来。超出目标、预算、权限或重要约束时停下相应动作，继续无关获准部分。
