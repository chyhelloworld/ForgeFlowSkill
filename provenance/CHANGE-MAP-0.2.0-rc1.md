# FF 候选包 0.2.0-rc1：设计环节与交付边界

在 0.1.0-rc1 冻结候选上复制演进，旧版与产品保持不变。五份可独立使用技能：FF-Grill 1.5.0-rc1；FF-Design、FF-Prove、FF-Plan、FF-Deliver 0.2.0-rc1。无需每次顺序全跑。

## 本轮变更

- 新增 FF-Design：依据用户对界面审美的负面反馈与补入设计的要求，明确真实画面/版本、用户价值、参考提取、信息层级/布局/文字/状态/动效/品牌一致性。新方向先交少量实质不同的可见关键页候选，真实用户选择；已有明确设计的小改不强制多方案。可否决平庸方向，但不保证自动漂亮。
- Grill：将体验目标、平台、品牌和已知偏好并入原单一需求锚点，不新增问卷或文档系统。
- Prove：从泛视觉探索收敛到实际交互/技术/架构未知；不以模拟用户或实验成功代签真人审美。
- Plan：引用已选可见目标，按主要业务拆分；未选方向前不安排依赖该方向的整站开工。
- Deliver：最终实际渲染对照选定方向，操作主要业务路径；补目标 OS/shell 与用户实际运行入口。依据已报告的 Windows shell 环境变量脚本不兼容案例改进验证边界，不宣称该缺陷已由本技能包修复。
- 包装：五技能 UI 元数据与静态完整性检查；保留旧来源、许可证和改动映射。来源记录使用便携逻辑路径，未包含截图、私人会话或笔记正文。

## 证据与限制

本版由父任务安排独立行为评估；作者只做静态检查，不预写行为结果。静态通过不证明设计质量、真人接受、Windows/T3 安装或模型行为。设计候选尚未用于重做用户产品，没有选定新风格，没有修改现有 H5。原有 MIT 来源/固定提交及 FF 基线许可边界保留，未新增第三方设计素材或复制专有设计技能正文。

旧版逐项来源见 provenance/CHANGE-MAP-0.1.0-rc1.md 与 provenance/sources.json；本轮来源和变更边界见 provenance/design-change-sources.json。安装边界见 INSTALL.md。本包不包含测试报告中的私人输入或截图，也不提供安装成功承诺。
