# FF 0.3.0-rc4：三类独立审核

基于冻结 0.2.1-rc1 的独立副本。仅修改 FF-Plan/FF-Deliver 入口与相关引用，二者升为 0.3.0-rc4。FF-Grill 1.5.0-rc1、FF-Design/FF-Prove 0.2.1-rc1 保持逐字节不变。旧包和产品不改。

依据用户 2026-10-13 明确要求，审核分为主要流程/核心需求、代码规范（含复杂度/CRAP风险）、计划（含MECE）。每类分别给版本、证据、结论和重要缺口：计划在实现前及变更后，代码在形成差异后，业务在纵向切片及最终整合验收。可并行但不相互替代；复用已有记录，小改可短述，无三份长报告或固定多代理门禁。

MECE 检查目标不重不漏、交付责任、真实依赖与可执行验收，不把按文件分类当充分证明，不禁止共享前置或必要集成。

CRAP 参考原作者说明与工具规格，采用真实方法级圈复杂度及同版本覆盖数据；明确百分数/比例和覆盖口径。缺数标 NOT_MEASURED，不猜分，不把历史阈值当通用门槛，不刷覆盖率、不改变主要业务测试优先原则。未复制来源文章全文或安装新计量工具。

本包为候选，静态及有限单轮行为测试的证据在包外单列；不由文件存在宣称真实项目审核、Windows/T3安装或模型全面可靠。许可和既有来源保留；本轮来源见 provenance/review-change-sources.json。

最新用户补充：默认使用独立子代理/新上下文只读审核。小改一名可覆盖适用三类，复杂变化按风险拆分；输入原始目标、现行计划、冻结代码/diff及真实证据，不预灌通过结论。发现回实现者修复，再独立复核；不可用时披露独立性未满足。避免自检角色扮演替代独立上下文。

最新阈值补充：用户指定每方法 CRAP≤50 硬上限、约10或更低优化目标；逐方法检查，不取平均掩盖，未测不得当指标通过。区分本次实测/遗留范围，发现遗留超标不私自豁免。此为用户规则，不宣称官方通用标准。

独立 rc2 审核发现一条响应结论过宽：仅路径/依赖证据不足以宣布计划整类通过。该失败保留；本版针对性明确关键目标映射/验收缺证时整类待验证，并新上下文复测。

独立 rc3 复核提示入口导航可更清楚。本版仅将用户CRAP硬上限、优化目标及缺数据规则提前到代码审核入口；明确仅文案等无逻辑变更可说明计量不适用，而非把未测说成通过。重新独立复核该窄diff并复测边界/小改行为，历史证据不覆盖。
