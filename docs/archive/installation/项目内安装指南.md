# 项目内安装（0.6.0-experimental.7 Windows 中文路径修复候选）

实验7尚待最终 Windows 复验。前序 `windows-test.2` 已有 Windows full/doctor 和 Codex 技能发现证据，不能直接视为本候选已通过；具体边界见本文“Windows 与宿主验证”。npx 入口见 [npx 安装指南](npx安装指南.md)，main 可能仍为旧版，固定 Git SHA 只在发布并验证后提供。

## 快速开始

下载完整包后，先用可信发布回执的 SHA256 核对再解压；发布前使用已核对的候选包。工具源可放在目标项目的 `vendor/ForgeFlowSkill`，也可放在独立工具目录。目标项目必须已存在。安装器不下载任意版本，不做全局安装，不改宿主权限、MCP、登录、全局配置、项目规格或批准回执。CodeGraph 默认关闭。

首次使用需要 Node.js >=20.19.0；full 还需要 npm、Git、tar 和获取锁定依赖的网络。构建耗时受网络影响，不是离线一键包。

如果源码位于目标项目的 `vendor/ForgeFlowSkill`，从目标项目根执行：

```sh
node vendor/ForgeFlowSkill/installer.mjs install --project . --host codex --mode full --build
node vendor/ForgeFlowSkill/installer.mjs doctor --project .
node .forgeflow/ff-spec.mjs --help
```

路径含空格时加引号。Claude Code 将 `--host codex` 换成 `--host claude`；两者分别安装至项目 `.agents/skills`、`.claude/skills`。安装器一次管理一个宿主，切换宿主会迁移其管理的技能文件，保留用户额外文件。它不修改宿主指令、设置或斜杠命令注册。

## 工具源与目标项目分开

`--project` 可指定独立项目路径，不要求当前目录就是目标项目。相对路径以当前终端目录为基准；跨项目建议使用带引号的绝对路径。例如 Windows PowerShell：

```powershell
$FFSource = 'D:\tools\ForgeFlowSkill'
$Project = 'E:\projects\中文 项目'
node "$FFSource\installer.mjs" install --project "$Project" --host codex --mode full --build
node "$FFSource\installer.mjs" doctor --project "$Project"
Set-Location "$Project"
node .\.forgeflow\ff-spec.mjs --help
```

工具目录使用已核对的干净候选源码或完整包，不要手工添加/修改 payload 文件绕过来源清单。安装后业务命令始终从目标项目 cwd 运行 `node .forgeflow/ff-spec.mjs`；不要继续使用外置源码的 `tools/openspec/ff-spec.mjs` 作为已安装项目的业务入口。

## 只安装技能

```sh
node vendor/ForgeFlowSkill/installer.mjs install --project . --host codex --mode skills-only
```

这是明确降级：文件已放入宿主约定目录，实际发现仍需宿主验证；FF CLI 门禁不可用。doctor 与 launcher 均返回非零和 BLOCKED，不能声称 status/validate/验收门禁可用，也不能改用 PATH 中的官方 openspec。需要门禁时对同一项目重跑 full 加 `--build`。CodeGraph 不会被启用。

## 绑定与缓存边界

- 所有技能命令绑定项目内固定 `.forgeflow/ff-spec.mjs`，记录版本及源 MANIFEST SHA256；主入口验证已安装 release 的完整文件/链接清单，再使用现有 ff-build 进行 CLI 身份校验。
- `.forgeflow/install/state.json` 是安装所有权清单；release 在 `.forgeflow/install/releases`，备份在 `.forgeflow/install/backups`，恢复记录为 `pending.json`。
- full 内层的 HOME、配置、临时目录与部分缓存位于目标项目 `.forgeflow/install/local-home`；依赖构建数据还位于同项目 stage/release 下。npx 的 payload 临时解包目录也在目标项目 `.forgeflow/install/` 内。
- 工具源可以外置。使用 npx 时，外层 npm cache 可由 `--cache` 指定，外层 TEMP/TMP 可由用户在调用前显式设置；内层 full 构建会重新设置项目本地 HOME、缓存及临时目录，仍使用目标项目 local-home/staging，不支持完全缓存分离。
- 项目绑定与清单使用项目相对路径，设计为随整个项目移动；不要单独搬技能目录或手改绑定。移动后从新项目根重新运行 doctor，不能将此设计直接当作最终实验7 Windows 搬迁验收。
- 备份/release 不自动清理，升级会增加磁盘使用；本候选不提供卸载和垃圾回收。不要只复制 state 或删除备份后声称可回滚。缓存、构建与安装状态不要提交到项目版本库。
- MANIFEST 校验能检测意外改动，不是数字签名。必须先用可信发布渠道的包 SHA256 核对完整下载；攻击者同时替换源码与 manifest 不在该完整性校验的保证内。

这些设置不保证 npm、Git、系统或用户既有配置绝不写项目外文件；严格隔离需要在沙箱中验证实际工具行为。

## 重入、升级、回滚

同版本同来源、宿主和模式会完整校验后返回 UNCHANGED。任一管理文件被改动会停止，不覆盖用户修改。未管理的同名文件也会冲突停止；请自己决定移动/保留原文件后再重试，不要找强制覆盖选项（没有该选项）。

升级：将新包解压到另一个工具目录，核对发布 SHA256，再用新包 installer 对同一目标项目、宿主和模式安装。安装器保留旧版本和安装前备份。

```sh
node vendor/ForgeFlowSkill/installer.mjs rollback --project .
node vendor/ForgeFlowSkill/installer.mjs doctor --project .
```

工具源外置时使用其真实绝对路径。rollback 恢复上一个安装的准确技能和绑定，不回滚现行 `openspec/`、代码、policy 或批准。没有前版本会停止；首装不能用 rollback 当卸载。恢复后保留用户新增文件、历史备份与 release。修改过管理文件时，回滚也会拒绝，先保留并处理自己的修改。

## 中断恢复与构建失败

安装器在改技能前保存备份与 journal，逐文件原子替换，最后提交 state；普通写入异常尝试恢复旧版。硬终止后如有 `pending.json`，先确认没有安装器运行，再恢复：

```sh
node vendor/ForgeFlowSkill/installer.mjs recover --project .
```

若报告锁存在，确认进程已停止后仅手工删除空目录 `.forgeflow/install/lock` 再运行 recover。不要在另一个安装仍运行时删锁。恢复检测到文件既不匹配备份也不匹配预期安装结果时会停止并保留现场，不猜测用户修改。此实现不保证掉电/fsync 级事务，也不自动清理中断残留 staging。

full 构建失败时保留项目内 staging 供诊断，现有安装不变；排除网络/工具问题后重新安装，不改锁文件绕过失败。doctor 无安装时输出 Node/npm/Git/tar 依赖探测；已装 full 时校验运行时并实际调用 help。两个 doctor 的范围不同：包内 installer doctor 额外校验管理文件所有权；项目本地 doctor.mjs 只校验固定运行时并调用 help，不判断技能是否被用户编辑。READY 只代表本地 CLI 可调用，不代表规格有效、门禁通过、模型业务调用或用户验收。

## Windows 与宿主验证

原实验5在 Windows 发现两处问题：pnpm junction 指向 staging 绝对路径，stage 晋升 release 后失效；Node 24 `fs.cpSync` 在本次中文目录场景遗漏内容。

本候选修复路径为：

- Windows 使用 pnpm hoisted 布局，避免上述 junction 布局问题。
- 目录复制通过 `cpSync` filter 逐项复制，规避本次中文目录遗漏；原有链接、路径与完整性检查不放松，不允许绝对/逃逸链接。
- bootstrap 清理仅作用于安装器本轮新建的 stage；独立源码构建已有的 bootstrap 保留，不因独立 build 的成功或失败被这项清理删除。

前序本机 `windows-test.2` 已采用 hoisted 与逐项复制修复，full 安装、doctor 通过；真实 Codex app-server `skills/list` 在主目标项目发现17项 FF 技能。见 [Windows 前序试验摘要](../../../validation/windows/windows-test-2-summary.json)。这不是模型业务调用证据。Claude 未登录，未验证真实调用。

实验7还调整了 bootstrap 清理归属，最终候选尚需重新验证 Windows 中文/空格路径、full 构建、promotion 后 doctor/CLI、项目搬迁与真实宿主发现。Git/tar、网络、权限与路径错误按实际环境处理，不能把历史试验或可移植设计写成本候选已通过。

Codex 必须打开正确的目标项目，再核对17项技能发现与最小加载。不承诺聊天斜杠命令自动注册。宿主发现、模型业务调用和业务验收分别记录；安装器不为验证而修改权限、MCP 或登录。

## 后续业务命令

从目标项目根调用 `node .forgeflow/ff-spec.mjs`。`init --tools none` 等写项目命令仍需要原有任务授权；安装完成不会运行 init、改 specs、写 ff-policy 或制造审批。官方 OpenSpec 可共存，但它能访问兼容 specs 树且不执行 FF gate，命令隔离不是安全边界。

本轮变化见 [实验7变更](../changes/CHANGE-MAP-0.6.0-experimental.7.md)。

### 实验6失败与本轮复验

Node 24.12.0 原生 Windows 在中文路径下递归删除可能静默保留目录；实验6本机 full 安装失败，禁止发布。实验7对安装器拥有的新建 staging bootstrap 和独立构建固定 .build 使用不跟随 junction 的逐项删除，删除后检查实际消失；保留 staging 身份、祖先路径及运行时 inventory 校验，独立源码既有 .bootstrap 保持不动。

实验7的回归、逐函数 CRAP、精确 tgz 安装/doctor/CLI、重入、搬迁、临时目录清理与 Codex 17项发现结果保存于包外发布回执。历史 validation/windows 中实验6及更早的报告保留原版本身份，不作为实验7通过证据。冻结包后报告不写回包内；固定 Git SHA 验证完成后另在 GitHub 安装回执提供可复制命令。
