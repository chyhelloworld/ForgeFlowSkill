# 测试资源生命周期

## 范围与默认行为

复用已有源码工作区和获准的项目验证根，不为重复检查复制一份完整开发工作区。`tools/installer/test-workspace.mjs` 仅管理它本次新建的 `ff-run-*` 子目录；不按名称扫描旧目录，不接受任意待删路径，也不清空 `FF_TEST_ROOT`。该根必须预先存在、为绝对路径且路径祖先不是 symlink。所有 installer `.test.mjs` 的临时夹具统一通过 helper 放入指定根，缺失配置明确失败。其他 Python、review 或原生发布验证入口不在本次统一范围内，仍需分别核对其目录与收尾。

```sh
# 将路径换为已获准、源码外的现有项目验证目录。
export FF_TEST_ROOT=/path/to/project/_verification
node tools/installer/test-workspace.mjs
# 默认打印 PREVIEW 并保留现场。需要本次成功后收尾时，运行前明确选择：
node tools/installer/test-workspace.mjs --clean-success -- tools/installer/tests/resource-workspace.test.mjs
```

无参数时 wrapper 自动枚举 installer 测试，不需 shell 展开通配符。直接 `node --test` 仍可使用，但只创建夹具，不自动删除；日常回归优先 wrapper。默认预览是本次运行结束后的计划，不是删除旧运行的入口。确认不需现场时，在启动检查时选择 `--clean-success`，避免反复默认保留导致积累。旧运行需人工核对归属、所需证据与备份后再处理，不能用批量 glob 删除。

## 清理门禁与保护

- wrapper 保存本进程独占创建目录的设备/文件身份和随机凭证，校验父目录、子目录、凭证及祖先路径后才可清理。旧目录或新替换的同名目录不会被当作本次所有物。
- 默认只预览；只有明确 `--clean-success` 且子测试进程正常退出 0 才执行。测试失败、启动失败或被信号中断时不开始清理；删除前所有权检查失败不开始删除，删除过程中异常则可能部分残留。父进程被终止也不会触发 exit 删除钩子。
- 重要证据应保存在本次临时目录外的验证/证据目录。需要保留现场时，在本次树内任意位置创建 `.ff-preserve` 文件或目录；即使测试成功也不清理。运行日志应写到本次目录之外。
- 清理逐项 unlink 文件/链接和 rmdir 目录；每次遍历与子项操作前后复核祖先/目录身份，已识别的链接只 unlink 本身，检查最终目录确实消失。异常不被吞掉；可能部分清理时打印失败及目录位置，不声称完整保留或成功回收。
- 仅清理本次生成的测试夹具及其合成备份。用户项目、安装回滚备份、冻结证据、已有工作区和共享缓存都不属于可清理对象，不将其移动进临时树。目录必须为可信、无并发修改的测试空间；文件身份检查不是对恶意并发写入的安全沙箱；Node 路径 API 没有 dirfd/openat 绑定，仍有检查与使用间的竞态窗口，有外部并发写入可能时不得执行清理。

## 中文路径与平台证据

历史 Windows `rmSync(..., recursive: true)` 对含中文/空格的夹具曾留下目录。当前 helper 采用逐项删除和消失校验，不依赖固定 ASCII 重命名槽位，也不会覆盖同名备份。回归包含中文空格目录、合成备份、用户兄弟目录、替换目录、凭证修改、symlink 与成功/失败子进程。Linux 上通过只证明 Linux 行为；真实 Windows 仍需单独执行 `resource-workspace.test.mjs`。symlink 权限不足标 SKIP，不能报全覆盖或 native Windows PASS。

清单枚举同时排除 `.git` 文件与目录，避免 worktree 指针泄漏进 payload；此静态枚举测试不能替代重新打包、tar 清单与哈希验证。

## 删除被拒绝或结果不确定

自动审批器返回 `blocked by policy` 不是清理成功，也不代表改用另一个命令就获得授权。遇到拒绝立即停止，不重复原动作、不换 shell/Python/工具绕过；保留错误、目标及可观察到的残留，先向操作者说明原因和安全下一步。仅在有新的有效授权并核对结果后才考虑独立的后续操作。

helper 的清理异常携带结构化结果，runner 原样输出并非零退出：

- `CLEANUP_BLOCKED`：删除前检查拒绝，或 EPERM/EACCES/策略拒绝且没有已确认完成的删除。
- `CLEANUP_INCOMPLETE`：已有删除确认完成，但目录仍存在，不能声称现场完整保留。
- `CLEANUP_UNKNOWN`：操作结果或最终状态无法确认，不能声称已删除，也不能盲目重试。

结果包含路径、操作、错误代码/原因、已确认删除项数、根目录存在状态和下一步。项数只统计已成功返回的调用，不推断报错调用未执行；权限拒绝代码也只是观测结果。首次清理失败后，该句柄锁定原错误，再次调用不会重新删除。人工核对时不要先删失败现场或备份。

测试模拟 EPERM、EACCES、`blocked by policy` 文本、部分删除后拒绝及删除已执行但响应失败，证明状态区分和不重试。真实 Codex 自动审批器拒绝路径未实测，模拟不等于真实审批验证。

真实 auto-review 若在启动整个 exec/shell 前拦截，helper 根本不会执行，也不会生成上述结构化回执。调用方必须依据工具拒绝结果报告 BLOCKED，不能声称 helper 已运行或已产出回执。工具返回结果不明确时，先只读核查目标及残留，再决定后续步骤，不改用其他删除命令。文件系统拒绝模拟不表示已经与真实审批器联通。
