# Docker 构建与测试资源约定

仅当获准的项目实施或测试确实使用 Docker / Compose / BuildKit 时加载。先检查项目已有 Dockerfile、Compose、脚本与资源约定，复用现有机制；不为不用 Docker 的项目新增容器、资源管理服务或后台清理器。本契约是执行指导，不是自动清理实现，也不扩展工具权限。

## 构建复用

- 先核对 Docker context / daemon endpoint、项目、构建上下文与参数。镜像标签只是引用，不是内容未变的证据；记录源码/锁文件/Dockerfile/构建参数及基础镜像的版本或 digest，输入变化时正常增量构建。
- 优先使用同一构建器与已有缓存。镜像使用项目既有稳定开发 tag 或可追溯的内容版本 tag；不为每次重复测试生成随机 tag，不覆盖他人共用的标签。不要默认 `--no-cache`、强制拉取或重建所有服务；只有明确的干净构建/基础镜像更新需求才单独运行，并说明成本与结果。
- BuildKit 缓存可能被多个项目共享，不能假设镜像/container label 能隔离缓存。缓存与镜像默认保留复用；不执行全局 `docker system prune`、image/volume/network prune 或 builder/buildx prune，不把磁盘压力当全局清理授权。需要回收时先报告占用、归属及具体方案，另按权限处理。

## 本轮资源归属与保护

启动前在既有任务日志内记录本轮运行标识、endpoint/context、项目/Compose project 名称、用途及预计保留时间，不另建资源数据库。只读记录创建前已有服务、容器/网络完整 ID、卷与需保护对象；无法建立可信基线时停止依赖归属的删除。

只给本轮新建的临时容器/网络加项目和本轮 label，创建后记录返回的完整 ID 与证据；Compose 使用本轮专属 project 名称。名字、前缀、创建时间或 label 单独都不足以授权删除，不能给旧资源补 label 以取得归属。创建返回失败/超时可能已生效，先只读核查，不盲目重复 create。

以下默认保护，不纳入本轮清理：创建前已有服务、开发服务、数据卷（包括匿名卷）、bind mount 用户文件、数据库、备份、证据、共享镜像、共享缓存及未知资源。临时测试优先无持久卷或既有获准测试数据机制；不能为方便收尾把用户数据移入临时范围。外部网络、其他轮次资源与他人容器也不属于本轮。Compose project 中混有既有资源时不能整组 down。

## 成功、失败与中断的收尾

运行前确认本轮允许停止/删除的确切临时对象及保留策略；已有授权覆盖时不逐次询问，但不能跳过平台要求的审批。默认只报告收尾预览。选择自动成功收尾时，只针对已确认本轮新建且可丢弃的容器/网络，按完整 ID 操作，不用 glob、批量筛选删除、`down -v`、`rm -v` 或强制网络断连。

收尾前先再次核对同一 endpoint、完整 ID、本轮 label、基线与当前用途，再停止核实归属的本轮写入者、保存日志/测试退出码到临时资源之外；删除前再次复核。网络仍挂接任何容器或存在并发使用/归属疑点时保留并报告。按容器后网络的顺序逐项处理，删除后只读确认对象不存在；同名替换对象不继续处理。检查与使用之间仍可能有并发变化，label 不是安全沙箱；不能排除共享/并发修改时不清理。

- 成功：按预先选择的策略保留或收尾；报告实际删除、保留与残留，不能把测试成功等同资源已回收。
- 失败：默认保留本轮现场和证据，报告仍运行的临时容器、端口与资源成本；如有明确预授权的失败停止策略，仅停止核实归属的本轮容器，不扩大为删除数据。
- 中断：SIGINT/SIGTERM 的处理器只能尽力记录与执行预授权的停止策略，不保证执行；SIGKILL、断电或宿主退出可能没有收尾。下一轮先只读盘点残留，不自动接管/删除上一轮资源。
- 重复测试：复用镜像/缓存，每轮记录自己的临时容器/网络；连续三轮核对成功收尾没有新增容器/网络残留且保护对象未变。失败/中断留下的资源须单独列明，不能为了“零残留”擅自删除。

## 拒绝与不确定结果

`blocked by policy`、权限拒绝或审批取消时停止该动作，不换 shell、命令、工具或 endpoint 绕过，不隐式重试。记录确切动作/目标、原因、已完成部分及残留；拒绝发生在 exec 启动前则程序没有运行，不能伪造脚本回执。仅在有新的有效授权、确认前次未执行后，才按平台规则考虑后续尝试。

返回失败不证明未执行。超时、响应丢失或最终状态不可读记 UNKNOWN，先只读核查，不宣称删除成功或完整保留。已确认部分删除记 INCOMPLETE，确认未执行的拒绝记 BLOCKED；仅确认目标消失才记 REMOVED。测试业务结果与收尾状态分别报告，不能吞掉清理错误或用它覆盖原测试错误。

## 验收与证据层级

按实际能力分开报告：静态检查只证明契约存在/分发一致；模拟只证明测试模型或替身，不证明 daemon 或审批器行为；真实 Docker 才能证明指定 daemon 上的构建复用、生命周期与保护对象；真实 Codex 会话才能证明该宿主实际读取并遵循指导。缺少任一能力记 NOT_RUN/BLOCKED，不能从下层推导上层通过。

真实 Docker 验收仅在获准的隔离测试环境中执行：同输入连续三轮构建/测试，检查缓存命中日志、镜像 ID/引用、资源前后清单；验证成功、失败、中断、重复收尾、同名替换与未知对象保护。保护对象使用合成夹具，不能拿真实共享数据做破坏性测试。记录 Docker/BuildKit/Compose 版本、endpoint、输入指纹、命令/退出码、原始输出与实际残留；缓存大小/构建时间可变，不能将恒定字节数当缓存复用的保证。真实审批拒绝仅在实际发生时记录，不主动制造违规清理来测试安全系统。
