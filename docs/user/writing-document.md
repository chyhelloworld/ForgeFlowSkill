# 工作文档：先确认目录再补正文

`ff-writing-document` 是独立 0.1.0 元能力，适合需求、方案、报价、报告等工作文档。它负责内容组织和读者检查，不替代 Word/PDF 排版工具；文章逐段共创仍可选择 ff-writing-shape 或 ff-writing-beats。

可以说：“用 ff-writing-document，根据这些材料给甲方业务负责人写一份建设方案。先澄清缺口，再给章节目录。”

执行顺序：
1. 读取材料，复用已知的读者、用途与范围，只问会影响质量的未决问题。
2. 提出章节目录，每章可有一句范围说明，不抢写正文。
3. 你明确确认目录后，再补细节；修改受众/用途/目录时重新确认受影响结构。
4. 检查读者能否找到功能、角色、费用条件、依据和待决定事项，再检查排版。

小范围改错字不要求重新走全流程。对外文稿清除内部协作话语，但设备兼容、估算假设、价格条件不能删；内部纪要可以保留必要讨论。缺证据不能仅靠“以实际为准”补救，也不把合理估算一律禁止。

本技能可独立使用，ff-grill / ff-diagram 可用时按需复用；不触发全 FF，也不自动批准发送、发布或实施。明确读技能的测试不证明宿主自动发现或真实甲方接受。

首次从 17–20 技能安装新增本技能，应使用完整源包升级；已经安装后可以按[单技能更新说明](update-skill.md)独立更新，保留其他技能和运行时。恢复版验证和限制见仓库 validation/writing-document-recovery/README.md。
