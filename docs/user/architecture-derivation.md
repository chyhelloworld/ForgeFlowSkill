# 可选架构推导

`0.9.6-derivation.1` 在现有 **ff-spec 技术设计职责**中加入按需方法，不新增技能或CLI命令，仍为18项技能。ff-design 遇到业务职责/依赖缺口时可指向该职责，界面设计不会变成所有技术工作的前置。

AI 会结合当前意图、规则复杂度、模块协作、外部依赖及变化风险、已有架构和实现代价判断是否推荐。小 demo、简单局部改动或现有边界足够时默认跳过；复杂项目也只给简短建议，说明适用理由、能解决什么未知、需要补哪些工作，等用户选择。拒绝后继续原工作，不反复劝说；只有实质新信息改变适用性，才说明新的理由再推荐。

已发现该候选技能的宿主中可直接说：

> 用 `$ff-spec` 的可选架构推导方法，只梳理这个模块：沿已确认真实流程和异常分支，提炼业务概念、规则与状态，再说明职责编排、必要接口/外部适配和最小组装。关联现有需求与验收，保留未知，不实施。

主动请求就是选择，无需再次确认是否开始。没有选择时不读取推导模板、不偷偷完成推导；有会改变业务取舍的未知仍需必要澄清，技术事实可查的先查。可以只推导一个模块，也可以保持现有结构；不强制五层、每类接口或依赖注入容器。

推导材料来自既有需求、模块和验收。领域语言包括业务概念、规则、状态和约束，不只是DTO；要分别说明运行顺序与源码依赖方向。外部适配隔离协议差异，但保留同步/异步、能力不足和错误语义等真实差异，不承诺“换技术只改一个文件”。输出是简短的边界理由、需求关联、依赖约束、已知变化场景和验证方式；未运行写待验证，缺资料不编需求或收益。

这与独立 [`ff-architecture-review`](architecture-review.md) 不同：推导帮助解释“职责和依赖怎样划分”；评估比较“已有方案在需求/质量场景下怎样取舍”。两者独立可选、不自动互相调用、不互为前置；选择任一方法都不批准实现、重构、发布或改变安全权限。

本候选继承 `00c099f6e221e546a7aba2c7be900b6a32ac5083`，包含 intent-view 和架构评估。模板随 ff-spec 的 `references/architecture-derivation.md` 分发，独立安装不依赖另一技能目录。源码变更不会更新真实全局或项目安装；分发、显式读技能执行和宿主原生加载分别验证，不保证当前会话已有此方法。
