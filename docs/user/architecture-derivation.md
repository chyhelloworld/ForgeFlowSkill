# 可选逻辑架构推导

`0.9.6-derivation.4` 提供独立 **ff-architecture-derive**，共19项技能。它回答编码前的结构问题：应该分几层、各层有哪些组件、各负责什么、如何协作和约束依赖、目录怎样对应。无需先重走规格流程，可只分析一个模块；Spec整理行为/验收并推荐、引用成果，Design负责视觉，Architecture Review评估已有方案。

在已发现本候选技能的宿主中可说：

> 用 `$ff-architecture-derive` 推导这个项目的逻辑架构。先给层数与理由、逐层组件职责、依赖和目录映射；把关键需求及一条核心业务路径对应进去，指出遗漏、多造和关键假设。缺什么会阻塞请说明原因，只问最少输入；只推导，不实现或评估。

主动调用即选择，不重复问是否开始。一般设计中AI按意图、业务规则、跨模块协作、外部依赖变化、既有架构及代价推荐；小demo/简单局部变更默认跳过，复杂也只说明理由、可解决未知、额外工作，等用户选择。拒绝继续原先获准的独立工作，实质新信息改变适用性才再次建议。

主要产物是可检查的逻辑结构。沿一条核心路径，应看得出具体业务对象/服务、谁消费哪个契约或既有能力、谁实现、输入输出和重要失败、业务状态归谁决定；层框、栏目和英文接口名齐全不代表结构已清楚。少量文字链或关系表即可，没有图片也应能读懂，不要求类图或为每个模块造接口。

层数按当前范围决定，不从平台自动继承；在同一需求范围比较争议边界，例如入口独立与并入外侧适配，而非换成脚本/Agent选型题。合理四层可以保留，不强制三层/五层。已有Harness契约满足需求时直接复用，包装需说明真实语义/变化差异，不默认再造执行内核。源码依赖与运行调用分开，调查等业务状态、执行会话与平台任务终态各有权威，异步受理不能假装完成。只展开决定方向的连接和变化影响；部署、流程与风险说明作为补充，组装沿用最小入口。

目录先到层/模块级，每个组件有落点或未决理由，可共用目录；不提前穷举文件和函数。拟议路径明确标拟议，已核实路径注明事实来源。职责及依赖约束提前明确，格式/命名规范沿项目约定和工具，不新造规范系统。

遇阻碍时说明卡住哪个决策、最少需要什么、为何影响边界；可自行查证的技术事实先查，用户才能决定的取舍才问。非阻塞未知保留并继续完整的可确定部分，受阻部分给暂定/条件分支，不凭空造需求或要求前置问卷。

方案经用户确认后，引用在既有需求/设计/计划中作为实现参照；AI候选不自动变为已定架构。层内细节按原授权推进，需求或关键假设导致实质边界/职责/依赖变化时解释影响并走已有变更确认流程。不承诺架构永不变化，不另建基线系统。

推导与 [ff-architecture-review](architecture-review.md) 独立可选、互非前提，不自动实现或启动评估，也不替代强制安全审查。唯一模板位于新技能的 references/architecture-derivation.md；旧ff-spec只保留推荐和成果引用，不复制模板。未安装时应如实说明，源码/分发检查和显式读技能执行不等于原生加载。源码候选不自动更新真实安装，安装须有单独授权与回执；此前derivation.1真实反馈与原验证记录保留。
