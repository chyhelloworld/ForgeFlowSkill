# 可选架构评估

`ff-architecture-review` 是一个独立技能，包含一个按需场景参考，不是新增 FF CLI 子命令。它用于架构初稿后/关键定稿前、接手旧项目或准备重构；不必先跑其他 FF 技能。

在已安装并被宿主发现后，可请求：“用 `$ff-architecture-review` 比较这版架构与保持现状，关注这些需求和质量冲突。”支持斜杠技能的宿主可用 `/ff-architecture-review`。本轮只验证源码与隔离分发，不保证用户当前宿主已有命令，也没有升级真实安装。仅写名字不能证明已加载；临时显式读取 SKILL.md 是另一种执行方式，应如实注明。

Design 和技术方案流程只在适当时推荐入口：小 demo 默认跳过；复杂/跨模块、多质量属性冲突、难回退决策先解释收益、预计额外工作及视角，用户决定。未选择前不分析；拒绝后继续已获准的独立工作，不记为门禁失败、不反复劝说。风险实质变化可说明新理由重新推荐；既有安全权限与强制审查照常保留。

主动调用就是选择评估，不再问是否启动；范围不清才问重大未知。只借鉴需要的 SAAM 变化影响、ATAM 质量权衡或 CBAM 成本/效用视角，不串行强跑三套，也不声称正式认证。共享场景包括刺激源、刺激、环境、受影响制品、响应、响应度量并关联需求。

输出是短决策和证据：现状与候选、重要场景、推荐及代价、风险/未知和必要验证。保留“不改”方案；缺成本不编 ROI，定向实验需原授权覆盖，未运行不得写实测。入口本身不批准重构、发布或安装。

本候选 `0.9.6-architecture.1` 从 intent-view 的 `da0ce532332dc56da96bd399afa50019a0da5bf7` 延续：包含 intent.2 需求闭环、small-task.1 短路径、handoff.1 交接修复、intent-view 源码和本入口。另开的 self-use/small-task-trial/handoff-validation/review-contamination 记录不是因此自动集成；真实全局安装仍独立。分支/范围见[本轮计划](../../planning/ARCHITECTURE-REVIEW-096.md)。
