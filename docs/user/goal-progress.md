# FF 0.10：随时查看目标进度

本说明描述只读查询，不是后台面板、原生Goal API或新的任务系统。已有唯一计划、checkpoint v1和版本绑定回执仍是事实来源。JSON是可选机器入口；只有文字计划时由FF读取并说明证据缺口，不强制把小任务迁入JSON。

## 查看

在实际项目根目录运行（安装版）：

```sh
node .forgeflow/ff-spec.mjs status --goal checkpoint.json --current-goal R2
node .forgeflow/ff-spec.mjs status --goal checkpoint.json --current-goal R2 --json
```

源码版把入口换为 `tools/openspec/ff-spec.mjs`。路径按项目现有检查点调整，R2必须来自本次核实的当前目标，不能盲抄旧记录。需要Node与Python 3；skills-only可使用此只读路径，其余CLI门禁仍需full。查询不创建检查点、不启动构建、不补签回执、不更新目标、不执行项目提供的命令。资料缺失、Python不可用或证据失效明确报告，不自动补成完成。

视图包括：目标/范围及修订、唯一计划位置、已验证/待复核/未开始项、当前切片、最后运行观测、阻塞、最后有效进展、下一步和复盘建议。默认不输出完成百分比/ETA。查询时间、最后事实核查、记录时间和有效进展时间分开。

## 记录：扩展原有检查点，而非第二份计划

checkpoint v1 的项目根、dependencies、actions、goalRevision与回执规则不变。可增加 `progress`，缺失时保持旧数据兼容并显示未知。只在已获准记录的切片/验证/恢复/复盘时更新，查看时不写入。

```json
{
  "progress": {
    "goal": "完成已批准库存主流程",
    "scope": "不包含支付",
    "plan": "planning/current.md",
    "recordedAt": "2026-11-12T08:00:00Z",
    "lastFactCheckAt": "2026-11-12T07:55:00Z",
    "currentActionId": "T2",
    "nextStep": "核查T2测试结果后处理剩余失败",
    "execution": {
      "state": "running",
      "observedAt": "2026-11-12T07:55:00Z",
      "source": "已脱敏的工具执行记录"
    },
    "checkpoints": [
      {"id":"C1","at":"2026-11-12T07:50:00Z","goalRevision":"R2",
       "verifiedActionIds":["T1"],"activeMinutes":30,"workSource":"已核查的本段活跃工作记录"}
    ],
    "retrospective": {
      "at":"2026-11-12T08:00:00Z","decision":"adjust",
      "reason":"重复修复依赖同一未验证前提","nextStep":"先做最小反例验证前提"
    }
  }
}
```

这是字段示例，不是可直接宣称通过的完成回执。action的done只有通过现有resume版本/依赖/回执检查才算已验证；声明verifiedActionIds并不构成证明。执行观测始终是最后已知状态，当前活跃状态在本查询中为unknown；即便时间很近也不能充当实时进程检查。已暂停不证明子进程已退出，恢复不证明旧副作用已完成。

有效进展可以是验收结果、定位阻断或排除关键假设；应将其映射为现有计划的可验证动作和证据，而不是为了统计把每次日志写入拆成动作。重复完成同一项不算新增进展，改写recordedAt或复盘本身不重置计时。旧目标证据需复核适用性，不改签回执、不凭勾选继承。

## 停滞/低进度复盘

可通过 `--stalled-minutes 120 --slow-checkpoints 3` 选定试验阈值；数字是本版可调整默认建议，不是用户承诺的硬限制。只使用有来源的活跃工作时间；无法可靠计算则按检查点证据判断，不能用墙钟冒充工作时间。查询只给复盘建议，真正的停下复盘在既有目标步骤返回/切片边界由FF执行，不是定时唤醒或强行终止工具。

暂停、等待审批、外部输入和最后已知运行状态先核查，不自动按卡死处理。长构建有合理活跃证据时不重复启动。相同未经证实前提连续失败时可以提前人工触发retro，无须为了凑时间继续失败。

复盘只回答：目标缺口是什么、发生了什么有效变化、根因是哪类、一个最小新步骤是什么。输出continue/adjust/help/stop之一；不降低验收、扩大范围或权限。复盘后没有新依据不得重复原尝试。用户取消优先；查看进度不恢复工作。

## 当前边界

可验证的是投影和触发逻辑，不是原生Goal同步、后台调度、模型读取保证或真实进程监控。检查点及证据需要按既有流程及时维护；来源文本存在不等于真实活动已被独立验证。真实宿主行为、Windows及审批器需各自运行验证，不由Linux单元测试推出。

活跃分钟是相邻检查点之间的实际工作时长，不得超过其墙钟间隔。历史引用失效/旧修订证据时先标UNKNOWN并复核，不能反推当时没有进展。上次复盘已经覆盖最新检查点时显示FOLLOW_RECORDED_DECISION，它不刷新有效进展计时。
