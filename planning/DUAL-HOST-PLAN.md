## 用户目标与边界

同一项目同时保留 Codex `.agents/skills/ff-*` 和 Claude `.claude/skills/ff-*`，两端共用一个受版本和 manifest 约束的 `.forgeflow` 运行时；任一端可独立检查入口。保留旧单宿主使用方式、用户修改保护和可恢复事务。安装就绪只证明文件和 CLI 可用，不证明两个模型实际调用、业务正确性或人类验收。

不做全局安装、真实产品修改、发布、部署或 Hindsight 接入。main 合并遵守后续单独授权和仓库门禁，不自动晋级其他项目。不增加模型协调器、每端运行时或第二套状态数据库。后续方法改进只进入现有路线图。

## 参数与状态契约

| 操作 | 行为 |
| --- | --- |
| `install --host codex\|claude --mode full\|skills-only` | 保留旧单宿主语义，包括旧单端切换。已是双宿主时拒绝隐式删端，提示明确操作。 |
| `install --hosts codex,claude --mode full\|skills-only` | 显式安装/升级两端，输入顺序规范化；拒绝重复、未知值及与 `--host` 混用。 |
| `doctor [--host codex\|claude]` | 无参数检查全部已装入口；指定端检查该端及共享文件/运行时，未安装端阻止。不是实际模型调用。 |
| `remove-host --host codex\|claude` | 只删除该端有哈希记录的文件；另一端、用户额外文件、共享运行时保持。未安装端返回不变；最后一端拒绝删除，本轮不做卸载器。 |
| `rollback` / `recover` | 保留项目级整笔事务语义，回退前一整套宿主/版本/模式。中断后先确认进程结束再移除空锁并 recover。 |

所有操作继续要求 `--project`。`full --build` 明确允许构建所需依赖下载；`skills-only` 门禁仍 BLOCKED。两端采用同一个版本、manifest、mode 和 release，更新一次原子提交，不支持混合版本/模式。

旧 schema 1（`host`）继续可读，未变化重入不改状态字节；首次显式双端安装迁移到 schema 2（规范化 `hosts`），单端移除后保留 schema 2。schema 2 校验声明宿主、托管路径和每端 17 个 SKILL 必需入口的交叉一致性。仅迁移需要的状态，不重写旧历史。所有变更检查全部托管文件；任何一端的用户修改都阻止变更。`doctor --host` 可隔离另一端普通文件的内容损坏，但仍拒绝不安全路径/畸形状态。

## 最小实现

1. 解析参数，抽出共享状态/宿主路径校验，避免安装器与已安装 doctor 各自解释 schema。
2. 组合两套 skill payload；共用 launcher/runtime/doctor，并分发其所需 `state.mjs`、`files.mjs`。skill 绑定写明宿主和对应 doctor 命令。
3. 安装与移除使用原有 lock、journal、backup、state-last 提交。每项变更（含升级、切端、移除、回滚）同时核对当前共享 releaseInventory，运行时被改也须保护。字节相同的文件不重复写；移除单端不递归删目录。回滚仍为上一整笔项目安装。recover 已提交分支核对 after 文件集合、状态及实际字节后才清 pending；新 journal 增加最终状态哈希，旧 journal 仍校验已有文件信息。state 原子写入前失败恢复原字节；state 已提交后清 pending 失败，核验后承认 COMMITTED，不能伪称已回旧版。
4. doctor 检查宿主入口文件哈希、共同依赖和实际 CLI 探测；源码入口与已安装入口均在 pending/lock 时阻止就绪。探测后再核对事务与状态，期间发生变化即阻止，不把并发快照当稳定 READY。
5. README、安装说明和现有路线图同步；17 个技能与版本、manifest、payload 一致。Goal/复盘策略不作语义变更。

独立审查发现两项实际反例并纳入修复：transaction 损坏不得误走未提交恢复；full 构建期间的用户编辑不得被提交覆盖。提交前重核当前状态、全部托管文件与共享运行时，备份/应用时也验证字节，最终文件与 release 完整性通过后才写 state。schema 1 的单端 JSON `host` 输出保留，另补 `hosts`；schema 2 只用明确的 `hosts`。
