## 复用与最小方案

| 现有能力 | 本轮缺口与最小增量 |
| --- | --- |
| Grill 单一锚点、最新确认、记录模式、决策索引 | 展示提炼后的需求；原话为按需追溯；持续吸收普通项目对话；统一探索/决定与转向影响 |
| Intake / Handoff 状态核实、受影响功能基线审查 | 本次相关行为先观察，已确认/观察/推断未知分开；一次可跳过的未知对齐 |
| Spec / Plan、稳定任务 ID、v2 progress | 原规格/设计内加稳定需求与模块引用；多对多关系与独立跨模块验收；不把勾选当需求通过 |
| Design / Prove / Implement 旅程、原型、真实证据 | 同一用户场景同时约束 UX 和架构；按三档扩展依据设计；先完整纵向切片 |
| Review 最小阅读、三类结论、局部复核 | 需求/实现差异与跨模块证据进入原综合审查；不增加每任务审核 |
| Deliver / Handoff / Retro、既有健康/恢复脚本 | 任务/切片末或失败中断时一条轻量评价与问题记录；深入复盘仍按需 |

选择：技能内短接线 + 一份需求闭环契约 + Spec 内可复制的引用示例 + 轻量反馈规则。沿现有独立安装约定，相关技能携带同源引用副本，检查字节一致；不为每项技能创建项目事实库，同会话无变化不重复加载。关联数据放已有 design/任务载体的 `intent-links-v1` JSON 块或一个旁置索引，正文/状态仍在原权威记录；普通小改直接内联，不强制 JSON。独立审查F1补齐：单独使用任一技能结束任务也有评价入口，十个闭环技能读公共最短规则，其余独立职责带反馈引用，Deliver/Handoff/Retro可按需展开格式；最后收尾者更新一条，已有评价不重复。

替代方案：仅增加长文提示最便宜，但后续无法可靠读取关联；新增统一数据库/CLI 状态机可做自动进度，却引入第二权威与迁移成本。本轮选引用格式，明确它不会自动使证据 stale 或证明批准；现有 policy/artifact/dependency 继续负责有效性。
