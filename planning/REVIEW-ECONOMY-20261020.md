## 目标与验收

让人仍能判断 AI 是否偏离原始目标，减少逐任务启动审核和重复装载材料。阶段是一份可独立验收的功能切片；不能无限延后至整个项目结束。普通任务先自检及确定性检查，一名独立读者在阶段末分别判断目标/主流程、计划覆盖、实现质量；有依据的专业视角才拆分。

关键变更（核心替换、主要用户路径、数据迁移、安全边界、验收口径变化）在实施前独立审方案；风险不以行数/文件数代替。用户额外审核要求、项目已启用门禁继续遵守。修复复核局限已发现问题及影响链，非阻断无关建议进待办；新关键缺陷继续阻断，不能用轮次/token上限放行。未知分流为最小实验、需求澄清、计划补漏、审查冲突裁决。

最小证据包含原始目标来源、不可破坏约束、验收、本次范围/差异、关键测试、已有结论与未验证项。摘要用于导航，按需读原文并检查跨模块影响。结论复用同时检查目标、规则、依赖/配置/输入及证据有效性，沿用 v2 绑定，不新建缓存。

## 全局影响与选择

- 产品/用户：降低普通切片审核启动成本，保留目标判断；更新用户手册与入口，防止旧指令恢复逐任务审核。
- 职责/耦合：沿用 Plan / Implement / Review / Deliver，不新增技能或流程控制器。以既有生命周期契约同步的安装内副本传达统一时机，Review 保存审查细则。
- 状态/数据：不增加第二套事实库，复用 v2 snapshot/report/inputs、Git 与唯一计划。摘要不取代原始证据，未登记依赖仍须人工发现。
- 控制/权限：不改 CLI、policy 或 CRAP 阈值。既有 `reviewRequired:true`/progress 计划审核门禁可能要求实施前回执，必须满足；新默认不绕过它，也不把自检签作独立 pass。此轮因变更审查口径先做独立方案审核。
- 质量/可靠性：六类正反例覆盖普通切片、关键升级、局部复核、失效条件、关键未知、跨模块回归；确定性 v2 回归证明绑定仍在。不把静态文本检查当模型效果。
- 成本/演进：最小文档/路由修改，比较实际审核启动和阅读记录；构造对照仅为代理指标。没有账单 token 数据就标 unknown，不承诺节省百分比。不建评测平台。

沿用所有前置审查会保留频繁调用；新增调度/缓存框架成本过大。选择调整既有触发、证据包和复核约定，显式保留更强项目门禁。旧安装位于工作区根 `.agents/skills`，为 `0.6.0-experimental.5.windows-test.2`；本轮仅改 source 候选，不升级该安装。project-iteration 的架构参考资源读取失败，本节直接记录六视角核查，不声称读过缺失资源。
