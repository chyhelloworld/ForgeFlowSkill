# FF Writing Beats

1. 完整读取既有原素材，保持只读。使用不同的文章路径，拒绝输入输出同一文件或符号链接别名；位置未知问一次。与作者确认受众及已知概念。
2. 提供2–3个候选起始节拍，均来自已有素材。每个节拍说明依赖什么概念、新铺垫什么、开启哪些可能方向。概念尚未铺垫的路线不作为可直接跳入的候选。
3. 先等作者选择，再只将选中的一个节拍写入文章，立即停下。一个节拍只完成一个叙事动作，可一到数段；禁止预写后续或把未选择候选写入正文。
4. 每轮重读文章，绝对保留作者编辑；若作者改写或删除前文，重建“当前已铺垫”概念集，不能沿用过时清单。再提供2–3个可达的下一节拍，不提供空洞重复选项凑数；素材不足时问补充或收束。
5. 缺例子、经历、指标、引文和事实依据时询问或删除，不制造材料。必要新概念先用一个节拍解释，或明确重新确认受众前置知识。
6. 作者可要求重写一个节拍或回到较早分叉，精确修改指定内容并核对后续概念依赖，不擅自删掉其余作者编辑。旅程完整即可结束，不要求用完素材；作者可随时停止。
7. beats 与 shape 是替代路线，可以直接读取已有材料，无需先 fragments 或 shape。草稿完成、独立审核、归档均不自动授权发送或发布。

可选工作记录见 [模板](references/template.md)。

## FF 边界

这是按需方法，不是新增强制阶段；小任务可直接完成，不要求创建完整 OpenSpec change。已有项目的当前授权、范围和文档约定优先。不因健康检查、素材缺口或复盘扩大范围。未授权的外部发送、发布、安装、持久访问或安全设置更改必须停下交用户决定。

选择使用 CLI 记录时，稳定 artifact ID、显式文件路径与依赖关系应在项目 schema/FF policy 中配置；文件存在不等于通过，生成者不得自签独立 review。审核绑定当前内容与依赖指纹；上游变化后重新判定 stale。研究、素材、文章和复盘不是产品行为规格，不放入 change 的 specs/ 增量目录，不以归档冒充用户验收或发布授权。
