# 任务级使用评价与问题收集

在任务/可验收切片结束、失败或中断时，由最后承担收尾的职责附在既有交付/交接/任务记录中，一次即可；已有评价复用/更新。单独使用一个技能也适用，不强行调用其他技能；用户随时报告问题时立即收集，不等结项。不另跑完整 Review 或强制深度 Retro，不逐消息打分。Intake 只读时在回复中给结果；保存仍遵循已有本地授权，Mode 0 只在对话。默认不上传聊天日志，不读取不可访问的其他宿主历史。

先复用实际目标、差异、测试、失败日志及用户已给反馈；每维一短句也可。状态只用 **符合 / 问题 / 未知 / 不适用**，每项带依据与证据类型：**客观测量 / 用户反馈 / AI推断**；不适用需理由，AI推断不能改写成用户认可。不合成总分，缺反馈不等于满意。token、时长或重试等无可靠记录就“缺失”，文件数不是 token。评价是观察，不是新的门禁或审核 pass。

| 维度 | 要判断什么 |
| --- | --- |
| 需求理解 | 提炼的目的、约束和范围是否符合已确认意图；未知是否诚实保留 |
| 设计 | 场景、模块协作和方案复杂度是否服务需求；体验/扩展依据是否验证 |
| 交付 | 实际完整路径及验收证据是否满足；任务done不代替需求验收 |
| 变化适应 | 探索/决定是否分清；影响、复用、局部复验是否准确；没发生变化可不适用 |
| 成本 | 实际时间/token/重做/用户负担；缺指标为未知，不编节省比例 |

问题最小字段（可一段，不强制新表）：稳定问题ID；FF版本/宿主；任务目的；期望/实际；发生阶段与影响；复现步骤或证据指针；归因（客观证据/假设/未知）。失败、中断或工具结果不明保留原状态，不能只收集成功案例；敏感资料只留脱敏必要信息。每条评价引用问题ID，多个报告可归并为一个问题但保留各自证据和差异。

重要问题可触发针对性的深入复盘，普通问题在既有待办中归并；不为了凑改进每次制造候选。流程复用 ff-retro：**问题归并 → 原因与替代解释 → 最小改进 → 原失败和正常反例回归 → 真实任务复验**。没有真实复验就标待复验，脚本/合成对话通过不晋级成真实效果已证。规则缺失、规则未接线、未执行、环境问题和未知分开；每个问题不自动变成永久新门禁。候选有适用范围、保留/撤销条件；实施、晋级或安装仍按现有授权。

可用的最短记录：

```text
任务/切片与版本宿主：…；结果：完成/失败/中断/结果未知
需求理解：未知｜AI推断｜摘要待用户反馈，来源…
设计：符合｜客观测量｜同版场景证据…（仅支持所测范围）
交付：问题｜客观测量｜跨模块A-1失败… → I-1
变化适应：不适用｜本片无转向
成本：未知｜token缺失；时长仅在有原始计时记录时填写
I-1：目的…；期望…；实际…；阶段/影响…；复现/证据…；归因未知
下一步：归并到已有问题/最小验证；真实任务复验待进行
```
