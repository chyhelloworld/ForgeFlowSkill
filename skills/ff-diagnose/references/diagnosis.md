# 诊断反馈与证据

- 按场景选现有测试、HTTP/CLI、浏览器主旅程、脱敏 trace replay、最小 harness、差分或二分；优先最小安全、快速、可重复的反馈，不要求安装新工具。
- 命令必须命中用户症状并能失败，不能只看“进程退出0”。记录执行环境/版本、输入来源、期望独立依据、实际输出、退出码及日志位置。输入含敏感数据时先脱敏，禁止将凭据写入日志/命令/报告；权限不足则停在所需确认前。
- 间歇故障固定 seed/时间/依赖，记录重复次数、失败次数及环境；为已授权资源范围设有理由的运行预算。不能把一次未出现或人为高压触发率写成根治证明，不以固定100/1000次代替判断。
- 性能先记录版本、数据规模、硬件/环境、预热、重复测量及指标分布；比较同条件基线。无基线/环境不可比时标限制，不凭单次计时宣称提升。
- 每个候选写“若原因X，则改变Y会观察到Z”；每次只改变一个变量，记录反证/支持与剩余解释。探针用可搜前缀；删除只针对本轮获准产生的临时内容，保留项目已有日志与他人文件。
- 需生产仪表、额外付费、访问扩张或敏感操作时先按权限确认，不因诊断需要自动获准。人工复现可用短步骤与结果回传，不假装 agent 已运行。
- 证据最小结构：症状→原始命令/实际失败→缩减用例→假设/单变量观察→原因状态→修复版本/回归→原场景复验→残留风险。复用已有票/证据位置；无写入授权仅当前对话报告。
