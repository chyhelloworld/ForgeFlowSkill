# 有效证据与短反馈回路

## 最小验收可行性预检

在依赖验收能力的大规模实施前，核对目标平台和用户真实启动入口，用当前最小样例确认相关预览可达、关键操作能执行、证据可取得，以及本轮必要的独立审核上下文、计量工具和数据能否提供。复用仍有效的已有检查；不是提前要求尚未实现功能全部通过。低风险小改只核对相关入口与检查，不走全套。

预检失败先定位具体阻塞和依赖它的切片；在授权内修入口或提供最小待决定项，独立部分可继续。目标平台不可达标 BLOCKED/NOT_RUN，计量缺失标 NOT_MEASURED，独立性不可用如实披露；不得靠替代平台、模拟或实现者自评宣告通过。最终版本仍须跑正式验收，预检通过不等于交付通过。

## 主要业务流程优先

主要业务旅程真实走通、变更影响回归是测试重点。复用计划的最小验收面，不按函数、字段或异常穷举，不追求覆盖率/数量。没有明确业务保护价值不增加测试；数据丢失、权限或已出现缺陷等实质风险才加少量专项。资料修改、纯视觉或简单低风险改动不强制 red/green、故障注入或业务测试全套。

## 从真实行为开始

按已有项目约定选择公开入口的测试，说明它能覆盖和遗漏什么；已有确认范围不重问。新增接口或明显增加验证成本才提出必要取舍。预期值来自规格、独立算例或已知正确结果，不能照抄被测实现再比较自身。

修 bug 先取得能触达用户症状的紧密反馈回路，按需减小输入、用单变量探针区分原因。采用 TDD 或能复现的业务缺陷修复时保留实际失败→修复→通过，不把它扩成所有任务的仪式；如果未得到可靠失败信号，如间歇性问题，只能说明假说与当前覆盖，不能编造 red。根据风险选择必要反例，不要求所有小改动故障注入或固定数量用例。

## 负例与非空运行

新增/更改检查器、测试门禁或以其绿灯作重要保证时，验证它真的能识别对应坏情况。注入只在获准隔离副本进行；先核对实际 diff/输入已变化，再执行并查看具体断言/诊断。结束还原或丢弃隔离副本，复测正常路径。

按本次验证目标区分预期诊断与无关失败。与目标无关的配置/类型/依赖/启动失败、没有改动或没有发现对象，不能冒充目标负例成功；类型门禁的预期类型错误等若正是目标诊断，应按实际症状判定。退出0也须核对测试数、扫描模块/文件范围或其他能说明实际工作发生的原始输出；0对象、全跳过或排除错目录应标证据不足。若任务本来就是检查空集，核对它确实应为空；空集不能证明检查器识别能力。没有计数输出时查看工具支持的发现列表/详细日志或已知输入，不凭空填数量。

## 绑定版本，不只写 PASS

复用项目测试报告，按风险保留能复核结论的必要信息：操作/命令、环境和必要工具版本、时间、对应 commit 与未提交/未跟踪内容快照或 hash（非Git工作区使用可复核版本标识）、实际退出码、原始输出及结果范围。简单检查无需额外造复杂记录系统。保存前去除凭据与无关敏感数据。文件名叫 green 或报告标题写 passed，不覆盖真实退出码和错误。

区分 PASS、FAIL、NOT_RUN、BLOCKED 与有理由的 N/A（或项目等价状态）。确认输出路径可读；无原日志则说明证据限制，不能补造。之前版本的绿灯不自动适用最后工作区；改动后重跑受影响检查。

## 回归与整体约束

修复后重跑原症状、相关旧行为和项目要求的整体命令。正常内容正向路径也要保留，防止加严校验让已有合法数据失效。聚合检查若中断，单测成功只证明那部分，不宣布整体通过。

从最新目标提取真正跨边界的约束，枚举本次受影响的生产者/消费者/输出，再在适当入口验证。例如内容真实性、排除规则、权限或金额语义可能跨页面、索引、导出、订阅或调用者；按实际产品选择，不复制博客的固定渠道表。相同输入跨调用者的合同应一致；只测共享 helper 不证明所有调用者正确接入。

UI变化看完整用户路径与组合状态，不只新增块。移动/桌面、重复或中断流程有实际影响才纳入；截图观察、交互运行、真实设备和用户主观接受各自标明。没有浏览器访问不要声称已看图或操作。

## 视觉目标与用户真实入口

对 UI 变更获取最终版本关键页面/状态的实际渲染，与选定目标在可比较视口下并看，检查层级、布局、文字、反馈和品牌一致性；说明实质偏差及其理由。操作主要路径验证滚动、主动作和相关返回/取消等，不只查控件或函数存在。未实际查看就标 NOT_RUN/BLOCKED，截图文件存在不代表已经看过；旧版截图不能验收新版。客观问题修复后复看，审美争议交真实用户，不靠评分或模拟接受通过。

先确认用户将在哪个 OS、shell、运行时/浏览器及入口使用，再执行项目承诺的真实启动/构建/预览/主要业务入口中相关部分。安装和启动脚本也是产品交付的一部分；直接调用底层命令绕开有问题的包脚本，不能证明用户入口已修复。

跨平台检查关注实际差异，例如 shell 环境变量赋值、路径/引号、文件名大小写及依赖启动方式；按项目支持范围选择修复，不机械引入新依赖。Linux 通过不能推出 Windows/PowerShell 已通过。无法获得目标平台时保留已证环境和未证入口，提供最小复验步骤；不得声称实机验证、原生安装或目标平台兼容性已完成。

若目标依赖动态/空间连续性，按 Design 已约定的真实输入从转场前走到转场后并观察全程，覆盖与目标有关的停下/返回；连同角色/对象路径、镜头与内容节奏一起判断。截图拼接或数值变化不能替代过程证据。交付前以原目标自查最明显未达处；核心体验未证或已有显著差距时，分列局部通过与整体待验证/未达，不用“全绿”“无重要问题”掩盖，不将连续性缺口自动降为最后润色。普通小改只检查受影响行为。
