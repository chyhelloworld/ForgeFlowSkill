# ff-implement 0.10.0

## 本轮一致性与复用（执行约定）

新增、修改、修复或替换界面、组件、业务逻辑、配置时，动手前读取[一致性与复用执行约定](references/project-consistency.md)，先定位相关已有实现、调用者与现行规范，再决定复用、扩展或保持独立；执行中同步处理本轮旧入口和受影响文档，不等事后复盘。仅审查时核实这些实际动作；纯文案或未触及的类别不展开，不为此新增流程或强制架构推导。

## 具体汇报

实质任务每次停下交还控制权（阶段完成、受阻、等确认、中途暂停、最终交付），用通俗短句说明做了/未做什么、涉及哪里、具体做法与实际结果；有后续才写下一步的对象和做法。涉及代码或文档改动时给已核实文件/模块，路径未知先说明并定位，不猜。默认关闭、未验证、失败/遗留问题及权限边界不能省略；不只报方法名、通过数量或“独审通过”。简单任务一两句即可，寒暄/普通澄清不套模板；证据和五维评价复用原记录，不重复展开。

## 先选择适用路径

低风险小任务：已确认目标/授权清楚，局部可逆，一个完整行为可用真实入口检查，关键状态/未知不阻塞，既有前置要求已满足。先核对适用项目约定/policy、真实工作区及未提交/未跟踪改动，保护已有内容；事实、用户确认、假设分别说明，readiness 不等于授权。

核心替换、主要用户路径/数据迁移/安全边界/验收口径变化、重大跨模块协作、已采纳转向、恢复状态不明，或既有前置门禁未满足/无法核实，都不走短路径。读取[完整职责](references/full-workflow.md)及其当前相关引用，按影响进入规格/计划/验证；关键风险须先独立审方案。不能以“只读”“几行”“小任务”降级授权或数据完整性要求，不关闭门禁、不补签证据。

## 小任务实现到收尾

复用确认来源与有效规格/计划；已授权且行为清楚的小任务，可在同一授权载体内联写目的、边界/不做项、验收入口/关键失败、未知，以及实际修改文件、模块责任/协作、具体改法与一条任务映射，再实现；路径未知先定位，不猜。没有实质歧义不重走Grill/Spec/Plan。目标或关键取舍不清先查事实，只问阻塞的用户决定。

先查相关已有工具避免重复建设；用真实入口实现一个完整行为，跑正常路径和关键失败fixture，记录版本/文件hash、真实命令/退出码及覆盖边界。只读工具不写输入、不读无关凭据/会话、不暗自扩大路径。保护数据与既有改动，未知运行结果先核实，不能重复未知写入。发现缺陷保留原失败→局部修复→受影响回归，不为指标刷测试或重建无关运行时。

切片末交一名独立子代理/新上下文读者，给确认来源、约束、验收、实际差异/hash与原始证据，分别审goal-mainflow/plan/code；作者自检不算独立。修复只复核问题及影响链，新关键缺陷仍阻断；独立性不可用如实披露。已有前置审核要求仍在实现前满足。

发起前按[审查短交接](references/review-handoff.md)检查实际委托：给事实定位，不附作者当前通过总评、通过数量摘要或认可暗示；保留原始结果、已知失败/风险和未知，必要历史结论标明版本/适用范围。原始PASS/exit 0不删改，可信同版证据可复用，不为避免诱导强制重跑昂贵测试；保存实际交接，不靠重审刷通过。

最后承担收尾的职责用短正文交代在哪些文件/模块改了什么、怎么改、真实场景结果及未知/偏差，附同版证据指针；有剩余工作才给具体下一步。五维评价在同一记录附一次，已有记录引用即可，不让评价挤掉上述说明：需求理解/设计/交付/变化适应/成本，各用符合/问题/未知/不适用+依据及客观测量/用户反馈/AI推断；无转向可不适用，token/时间缺失就unknown。问题用稳定ID记版本宿主、目的、期望/实际、阶段影响、复现和归因或unknown，不自动改规则。用户接受待反馈，不把测试/技术交付当接受或发布授权；无需额外加载Deliver才可收尾。

## 控制复杂度与校验边界

不为纯猜测的未来需求、异常或竞态增加复杂机制。新增防御前，在现有任务说明中简述具体失败路径、触发依据、影响、已有机制为何不足，以及实现和维护成本；没有概率数据就写“未知”，不编数字。优先最简单有效方案。超出已确认范围或显著增加复杂度时，先征得用户同意，不悄悄扩大改动范围；范围内必要检查不逐项重复审批。必要的安全、授权和数据完整性保障不能仅因概率低而省略；可分析的具体失败路径也是依据，不要求等实际事故发生。

外部数据在对应信任边界集中解析、校验并转为内部有效数据。同一信任边界内，同一条件未变时不要逐层重复校验；业务不变量由负责模块维护。跨越新信任边界、依赖状态变化或操作需要当前授权时，仍做必要检查。类型标注不能代替运行时校验，类型正确不等于业务合法或权限有效。先定位已有保障，再删减重复检查；事务、唯一约束和原子操作不是多余的类型校验。

审查只需回答：这项检查防什么具体错误？此前是否已保证？为什么要在这里再查？复用当前计划、差异和证据，不新增阶段、门禁或长表。

## Docker 资源（条件加载）

项目实施或测试使用 Docker、Compose 或 BuildKit 时，先读[构建复用与本轮资源收尾](references/docker-resources.md)。先复用已有镜像/缓存与项目脚本，只记录并处理本轮获准临时对象；保护已有服务、数据卷及未知资源。拒绝或结果不明确须报告，不换工具绕过。未使用 Docker 时不加载、不新增机制。

## 维护真实验证路径

沿用项目现有启动/测试命令与用户路径说明；改动使入口、就绪条件或结果判据变化时，更新同一处并运行受影响路径。只生成说明而未运行，标草稿/NOT_RUN；构建或 helper 通过不代替真实用户结果。没有验证入口时补最小可重跑路径，不默认新增工具、工作区或持久服务。
