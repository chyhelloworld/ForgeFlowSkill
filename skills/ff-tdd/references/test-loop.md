# 单行为循环与测试质量

1. 选择一个用户/调用者在意的行为，写清公共边界和依据。沿用已有同范围确认，不人为建立“每个测试必须再次问用户”的门禁。
2. 优先真实公共接口与组件集成；外部系统、时间/随机数等边界可使用受控替身并声明限制。不要 mock 自己的内部协作者、断言私有方法或只断言调用顺序；若项目特殊约束必须如此，明确该测试不证明真实主流程并补适用边界证据。
3. 示例：输入价格10、5，规格明确总价15，可断言真实 calculateTotal 返回15。若用同一个 reduce 算法构造 expected，则测试会复制实现错误，不能作为独立证明。快照也要有独立检查依据。
4. 真实 red 应有调用、时间/版本、输出、预期失败原因；green 用同一行为在修复版本重跑。可用安全隔离的负向控制确认敏感度；若人为变异，证明变异确已应用并恢复，不能污染真实产品或用户工作区。
5. 行为单位不等于函数/字段单位。不要求测试一切或追覆盖率数字；数据丢失、权限与已知缺陷可增加必要专项。仍须遵守 ff-review 的真实 CRAP 数据及 NOT_MEASURED 边界。
6. 若只有人工验证或宿主不可运行，明确不构成已完成 TDD；记录下一条可执行验证和阻塞，不能用模板、演示输出或模型模拟替代真实 red→green。
