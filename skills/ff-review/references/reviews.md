# 综合独立审查与局部复核

## 何时审查

普通任务先由执行者自检目标映射、计划覆盖及相关确定性检查；阶段末默认一次独立综合审查。阶段是唯一计划中可独立验收的功能切片，不是每个小任务、函数或技能调用，也不能无限延后到全项目结束；集成形成新的验收范围时检查受影响整体，不无条件重审每个已有效切片。

核心替换、主要用户路径、数据迁移、安全边界、验收口径变化必须实施前独立审方案，不能仅按行数/文件数判断风险。用户明确要求的额外审核、项目既有门禁优先：policy/progress 要求前置有效计划回执时仍须满足，不关闭 reviewRequired 或把自检签成独立 pass。新默认不迁移旧门禁。

默认一名独立子代理或真正新上下文审核者一次读取同一最小材料，分别给出三类适用结论；只有需要专业视角时拆分，不要求三人或三份长报告。审核者只读，宿主不支持独立上下文时标“独立性未满足”，作者自检和角色扮演不冒充独立通过。

## 最小证据包与原文

在已有任务/计划中按[审查短交接](review-handoff.md)给出以下内容或精确来源指针，不建第二套事实库。发送前去掉作者当前通过总评/数量摘要和认可暗示；原始运行结果、已知失败/风险/未知不可删改或隐瞒。同版可信记录可复用，不强制重复昂贵测试。接收后发现作者通过判断则披露，不宣称未接触或重审刷认可。

- 原始目标、最新确认来源、不可破坏约束与验收。
- 本次范围、排除项、基线和实际差异，包含未提交/未跟踪文件的可复核快照。
- 关键测试的真实入口、版本、原始输出与未运行范围。
- 已有结论的版本/适用范围、未验证项和已发现问题；既有结论作为历史证据，不当作当前预期答案。
- 总需求验收状态：适用子需求与跨模块场景的当前版本证据指针；未验收、未知、过期项分别列明，不用完成度或通过率代替。

不默认带完整聊天、全库或全部规格；摘要只作导航，不能成为唯一证据。先看原始目标及受影响实际内容，再按需定位规格/计划/调用者/配置原文，检验实现者解释。主流程必须检查跨模块生产者、消费者、共享依赖和整合约束；不能只读 diff 或以失败测试列表当影响边界。缺关键原文就标待验证。

同次审查内，当前上下文已读的相同原文片段，在内容、目标、适用规则、相关依赖/配置/输入及证据均未变时，复用其版本/路径/行号定位，不重复加载；仅在变化、新跨模块影响或具体证据缺口时补读并说明原因。首次仍读取原文，指针不替代证据，也不要求持久缓存或新增统计账本。

核实比较点可解析，说明直接差异或 merge-base 差异，不机械用 HEAD~1。展示实际文件清单；空 diff 先查比较点或遗漏工作区，确无变更则如实报告，不能称变更已审。

## 三类分别判断

1. **目标/主要流程**：从原始目标和最新确认检查遗漏、越界、全局偏离及跨模块约束。依据实际入口/操作/结果与版本走通承诺旅程；单测、规范或漂亮分屏不能代替。界面按[视觉目标审查](visual-review.md)核对同版关键画面、核心连续过程和用户基准，普通局部改动只查受影响目标。对方案选择，检查是否已排除更简单的可行替代；确无实质替代可记 N/A 并说明理由。
2. **计划覆盖**：目标映射、MECE 不重不漏、真实依赖、切片和可执行验收；核对每个已确认要求及跨片整合的落点。文件不同或责任互斥不证明完整。普通切片在综合审查中判断，关键风险提前审方案；有效旧结论只复核适用性。新增机制、抽象或状态库前，检查是否已有等价机制及为何不够。
3. **实现质量**：规范、复杂度、重复、职责、耦合、可维护性与回归可信度；区分硬规范和个人偏好。逐函数/方法 CRAP 硬上限≤50、目标约10或更低，按 [CRAP 数据与边界](crap.md)使用同版真实 CC 和覆盖率；缺数据 NOT_MEASURED，不能填估计值充通过。纯文案无相关逻辑变化可说明计量 N/A，不扩成全库计量或无关重构；仍做有证据的质量审查。

每类给结论（PASS / FAIL / 待验证 / 有理由的 N/A）、版本/范围、证据、重要缺口与下一步，可三行完成。关键未知不能判通过，也不能平均三类结论抵消主流程失败。缺总需求验收状态或账本时，目标/主要流程类只能判“待验证”，并列明缺哪一项。NOT_MEASURED 是计量状态，不能自动代表整类通过或失败。技术通过、用户接受、合并和发布分别判断。

## 外部审查后端（可选）

项目有 `openspec/ff-review.json` 且 `enabled` 不为 false 时，独立审查优先用已安装的 `.forgeflow/ff-reviewer.mjs`，而不是临时起子代理：先 `check --json` 看配置、后端可执行文件和认证提示，再 `run --brief <审查材料> --out <记录基名>`。配置字段 `backend`（codex|claude）、`model`、`reasoning`（codex: minimal/low/medium/high/xhigh；claude: low/medium/high/xhigh/max）、`enabled`、`timeoutSeconds`、`command`；环境变量 `FF_REVIEW_BACKEND/MODEL/REASONING/TIMEOUT_SECONDS/COMMAND` 和 run 参数可覆盖。run 写 `<out>.json`（含 L2、brief/config 哈希、命令、退出码、verdict/findings、usage、未验证项）、`<out>.md` 原始回答及 stdout/stderr；失败或超时仍保留记录并非零退出，不自动 fallback 到同模型自审，也不自动接受结论。

外部后端的只读限制靠 `codex --sandbox read-only` / `claude --permission-mode plan --permission-prompts none --bare --strict-mcp-config`，ff-reviewer 不验证后端真的没写文件；`independence: "L2"` 是配置声明的异模型，不是密码学证明。审查者可能因本机 MCP/沙箱环境读不到文件；brief 内嵌原文仍可审，但文件读取成功必须标未证明。没有配置、配置为 disabled 或后端不可用时才回到原独立子代理/新上下文流程；后端失败写 NOT_RUN/待验证，不改写成自审通过。修复复核用同一后端时重新生成 brief、附上一份记录和未关闭发现编号，不因“同一个 CLI”省略复核。

## 修复、分流与复用

发现交回实施者/相应负责人。修复后仅复核已发现问题、受影响依赖及必要回归，保留原失败；与当前目标无关的非阻断建议进待办，不扩大整改。复核中发现新关键缺陷仍阻断；轮次或 token 上限不能强制放行。相关范围扩大须说明影响依据，不能把局部复核误成只看改过的行。

## 审查者复用与复核

首次审查、关键变更前置方案、候选实质变化、出现新关键风险或原审查者已接触作者通过结论时，使用新上下文（L1）或异模型（L2），不复用。

同一候选、同一授权任务的修复复核复用原审查者，不新建子代理：只复核已发现的问题、受影响依赖及必要回归，保持发现编号、判据和未验证项连续。复用时由原审查者重新读取当前候选与证据哈希，不接受作者转述的“已修好”；在 `review.json` 记录 `reviewMode: "re-review"`、`reviewRound`（>=2）和 `priorReviewHash`（上一份 `review.json` 的 sha256），并明确这是复用复核、不是独立首审。

复用减少启动和重复装载；没有实际 token 数据时节省记 unknown，不能以复用把未复核范围签成通过。

技术未知转有判断标准的最小实验（ff-prove）；需求矛盾回澄清/规格；计划漏项改唯一计划；审查冲突先裁决。关键未知阻止依赖它的通过，不妨碍独立的无关获准工作，不按失败轮数机械切换方法。

复用结论同时核对目标、适用规则、相关依赖/配置/输入、目标内容和证据仍有效，不能仅凭源码相同。沿用 v2 的 snapshot/report、paths/requires/inputs 和证据绑定：把影响判断的原始目标与共享输入登记到相应范围，按需读原文，依赖失效沿影响链传播。CLI 不能发现漏登记的语义依赖；不能只刷新旧哈希洗成通过，也不另造缓存或结论存储。

同一授权任务可记录审核启动次数、实际读取文件/重复读取、耗时与缺陷发现。真实 token 数据可得时才报 token；不可得写 unknown，文件数、字符数、合成用例次数均为代理指标，不当实际账单或承诺节省比例。无需为此搭建评测平台。


## 控制复杂度与校验边界

不为纯猜测的未来需求、异常或竞态增加复杂机制。新增防御前，在现有任务说明中简述具体失败路径、触发依据、影响、已有机制为何不足，以及实现和维护成本；没有概率数据就写“未知”，不编数字。优先最简单有效方案。超出已确认范围或显著增加复杂度时，先征得用户同意，不悄悄扩大改动范围；范围内必要检查不逐项重复审批。必要的安全、授权和数据完整性保障不能仅因概率低而省略；可分析的具体失败路径也是依据，不要求等实际事故发生。

外部数据在对应信任边界集中解析、校验并转为内部有效数据。同一信任边界内，同一条件未变时不要逐层重复校验；业务不变量由负责模块维护。跨越新信任边界、依赖状态变化或操作需要当前授权时，仍做必要检查。类型标注不能代替运行时校验，类型正确不等于业务合法或权限有效。先定位已有保障，再删减重复检查；事务、唯一约束和原子操作不是多余的类型校验。

审查只需回答：这项检查防什么具体错误？此前是否已保证？为什么要在这里再查？复用当前计划、差异和证据，不新增阶段、门禁或长表。
