# 发起与接收独立审查的短交接

在阶段末发送审查时使用，可直接内联于委托，无需另建系统或强制新文件。发送者检查实际发出的文本和附件导航；不是要求审核者猜作者希望得到的答案。

```text
目的/来源：原始目标、最新确认原文或精确位置；执行者选择与用户要求分开。
范围/验收：本次行为、排除项、可观察成功与失败条件、适用约束/前置门禁。
变更定位：基线和目标版本、实际文件清单及hash/差异；dirty内容另绑定。
实现映射：需求→相关职责/任务→变更位置，仅导航，不给质量总评。
原始证据：命令、环境/时间、输入/输出/退出码所在记录、绑定版本、可复用范围。
风险/缺口：已知问题、失败、未知/未运行、部分产物与证据失效范围；不可隐瞒。
请求：独立核查goal-mainflow/plan/code，分别给结论、依据及未证范围；无预设判定。
```

不要发送作者当前的“已通过/没问题/只需确认”总评、通过数量的结论摘要、认可暗示或预期审核答案，也不要直接转发带这些判断的完成报告/完整聊天。原始运行输出中的PASS/FAIL、exit 0及实际断言结果是证据，不因“避免诱导”删改或遮去；提供原记录定位即可，不能选择性只给成功部分。

必要的历史独立结论须带来源、版本、适用范围及失效条件，并标为历史输入，不能充当当前预期结论。已知风险和失败必须同时给出；不以“盲审”为由隐去安全、数据完整性或其他真实风险。

审核者先核对目标与实际变更，再检查原始证据及适用性；同版可信记录可以复用，只对缺口/风险选择必要探针，不强制重跑昂贵测试。缺证保持待验证，不能用没有失败替代通过。若已收到作者当前通过判断，明确披露接触及限制，不声称未接触、不静默重新包装历史；按当前授权继续可独立核查的工作，不以反复换人/重审刷出认可。保存实际交接文本或可追溯原委托，结论仍由审核者形成，用户接受/发布授权另计。
