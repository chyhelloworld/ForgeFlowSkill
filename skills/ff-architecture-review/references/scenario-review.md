# 按需质量场景与候选比较

只在用户已选择评估后读取。复用已有需求/架构/证据，不要求填写完整问卷或先做三种正式方法。下列字段可内联成一段，未知写 unknown；度量目标是要求或假设，不能当作实际测量。

## 当前决定所需的颗粒度

按本次范围和决策双向检查：平台总览与单个工具准备实现不要求相同深度。关键路径的具体调用、输入输出、契约或现成能力、状态归属仍靠猜，是过粗；这些关系足以审查当前决定、其余可在下一步完善，是适度；穷举类/文件/函数、无理由接口包装或重复现成执行内核，是过细。指出原稿具体位置、妨碍哪个当前决定、最少补充或删减什么，不另开长清单。允许直接复用现有契约，不因缺类图或不是固定层数否决；资料未知标待核实，与已知缺陷分开。局部缺口只限制依赖它的决定，其余获准工作可继续，不自动改稿、实现或调用推导。

## 一个场景

- 场景 ID、关联需求/确认来源、架构版本与本次决策。
- **刺激源**：谁或什么触发事件。
- **刺激**：发生的请求、故障、攻击或修改。
- **环境**：事件发生的负载、运行或变更条件。
- **受影响制品**：系统、模块、接口或数据边界。
- **响应**：期望系统或开发过程如何处理。
- **响应度量**：有来源的阈值/时间/影响范围与验证方式；缺阈值不代用户编定。

按业务重要性与技术风险给少量场景排优先级，并标明这是用户确认、证据支持还是 AI 建议。无需给所有场景造分数。

## 按问题选择视角

| 当前问题 | 可借鉴视角 | 最少记录 |
| --- | --- | --- |
| 某次有依据的变化会波及哪里 | SAAM 的变化影响与场景交互 | 哪些场景现状直接支持、哪些需改；受影响模块/连接；多场景是否集中修改同一处及其影响 |
| 性能、可靠性、安全、可修改性等发生冲突 | ATAM 的场景优先级与风险分析 | 候选满足优先场景的依据；风险；敏感点（某决定对某质量响应影响大）；权衡点（同一决定影响多种质量属性），含受益与代价 |
| 预算有限，需要比较收益与投入 | CBAM 的成本、效用与不确定性 | 投入/维护/迁移及风险成本、对目标的效用、估计来源/区间与可信度；无可靠数据就定性比较或 unknown，不编成本、概率、ROI |

保留“保持现状/不改”并说明已知代价与未知；不要求现状无缺点才可选。对每个候选只列能影响当前决定的区别，不按三套方法逐项串行打分。本参考借鉴视角，不承诺符合各方法完整正式过程，也不构成 SEI 认可或认证。

## 假设、证据与简短决策

只对会改变选择的关键假设考虑定向实验：假设/反例、最小动作、所需权限与成本、停止条件、预期度量、实际结果及文件/版本。没有执行写“建议/未验证”；执行失败保留失败，范围外实验交用户决定。用户选择本评估不自动批准实验的外部动作。

短结论可用：`范围/版本 → 需求与场景 → 现状和候选 → 推荐/保持现状/暂缓及理由 → 代价与未知 → 验证证据/下一步`。需求是否满足、用户是否接受、是否发布分别说明，不由建议或测试通过推导。

## 方法来源（查证日期 2026-10-23）

这是依据公开方法概念与本轮用户要求新编的轻量参考，没有复制正式评估手册或引入第三方运行代码。

- [SEI：Scenario-Based Analysis of Software Architecture](https://www.sei.cmu.edu/library/scenario-based-analysis-of-software-architecture/)：变化场景、受影响组成和交互。
- [SEI：ATAM: Method for Architecture Evaluation](https://www.sei.cmu.edu/library/atam-method-for-architecture-evaluation/)：质量属性、场景优先级、风险及取舍。
- [SEI：Cost Benefit Analysis Method](https://www.sei.cmu.edu/library/cost-benefit-analysis-method-cbam/)：成本、效用与不确定性。
- [SEI：Integrating Software-Architecture-Centric Methods into XP，§2.2.1](https://www.sei.cmu.edu/documents/2056/2004_004_001_14348.pdf)：质量场景六要素。
