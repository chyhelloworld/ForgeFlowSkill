# FF Architecture Derive

首要产物是**可供用户检查的逻辑分层方案**：为什么分这些层、每层有哪些组件和责任、如何协作与约束依赖、拟落在哪些目录。业务流程/规则是推导依据，部署拓扑、现状审计和风险是补充，不能代替这份方案。可独立分析整体或一个模块；复用已有需求和验收，不强制先运行Grill/Spec或全套FF流程。

## 选择与范围

仅被Spec/Design推荐或因相关性读到本入口不代表已选择。结合当前意图、业务规则、跨模块协作、外部变化风险、既有架构和实现代价判断：小demo、简单局部变更、已有边界足够时默认跳过；复杂也只简短说明适用理由、能消除的未知与额外工作，等待用户选择采用、缩小范围或跳过，未选不读模板/不展开方案。

用户主动调用或已选择推导，直接按所选范围开始，不重复询问启动、不因小demo默认跳过而拒绝明确请求。拒绝后继续原先获准且独立的工作，不记门禁失败、不反复劝说；实质新信息改变适用性时才说明新理由再建议。

选择后才读[逻辑架构推导与产物](references/architecture-derivation.md)。先复用现有资料和用户确认，区分事实、AI拟议及未知；不要从代码现状倒推用户承诺。遇阻碍时明确“哪个决策被卡住→最少缺什么→为什么会改变方案”，可查的技术事实先查；只问用户才能决定且影响边界的问题。未知不填成确认，也不因为非关键缺口暂停全案或堆前置问卷；继续给不受影响部分，受阻处标暂定/待决定及影响。

层数按需求和耦合推导，不强制三层或把方法步骤变成五层，不为每类配接口。目录映射是设计建议时须标拟议，不能假称已查看或创建代码。以层/组件/职责/依赖/目录齐备的方案及必要未知收尾；关联关键需求并用一条核心路径核对遗漏或多造，供用户编码前判断方向。推导轨迹可简写，主观接受待用户反馈。

用户确认的结构才在现有需求/设计/计划载体中作为实现参照，不另建基线系统、不把AI候选自动标已定。后续层内实现细节按原授权推进；需求或关键假设变化造成实质边界/职责/依赖变化时，解释影响并回到已有变更确认流程，不能静默偏航，也不承诺架构永不变化。

`ff-spec` 整理行为、约束与验收并引用已选方案；`ff-design` 负责视觉；`ff-architecture-review` 评估已有方案。推导与评估独立可选、互非前提，**不自动调用评估，不修改业务代码、安装或启动重构**。本方法不替代既有强制审查、安全、数据完整性或权限要求；需实施时只交接建议，另按现有授权处理。其他技能未安装不阻碍使用本入口和本地模板。[来源与边界](NOTICE.md)。
