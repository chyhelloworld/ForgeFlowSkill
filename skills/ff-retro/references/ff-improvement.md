# FF 自改进：隔离候选，不改活跃版本

仅当用户主动指定 FF 本身为改进对象时使用；项目复盘仍走原流程。此约定复用已有候选、验证和审核，不是 `rsi` CLI、递归循环、自动改提示词或自动晋级引擎。

从一个真实偏差开始，区分需求/成功标准理解、FF 规则或实现、执行遗漏、测试夹具/环境和未知根因。核对已有机制与反例；证据不足就保留未知，不用新增规则替代诊断。只选择一个能验证的小候选，其余暂缓；用户只讨论设计时不改实现。

当现有授权覆盖最小补丁时：

- 使用隔离工作树、分支或候选副本，保留来源版本和自有差异。不要覆写正在使用的技能、自动更新安装或修改全局规则。
- 在实现前冻结旧版源、同一真实失败及正常反例、输入/环境、预期结果和判据。需要留出集时由独立上下文封存，作者不读改它；不为使新版本通过而改目标、权限、判据或留出集。新发现另列，不倒写原对照。
- 对旧/新版本实际运行相同对照，保留旧失败、新失败与修复、正常反例及未测项。权限不足的夹具记 SKIP/NOT_RUN，不能当 PASS；不靠放宽权限、换身份/模型或私有日志读取制造成功。
- 独立审核核心目标/主要流程、计划覆盖和代码，绑定候选版本与原始证据。逐函数计量缺可信同版数据仍为 NOT_MEASURED；作者自检不冒充独立通过。
- 交付候选补丁、短变更/风险摘要、证据、撤销方式和剩余缺口，保持“待用户确认晋级”。独立审核通过不替代用户晋级；没有确认，不合回默认使用分支、替换活跃技能、合并 main 或发布。

验证不支持假设或代价过大时撤销自有候选，保留原件与结论；有用的方法可以附到现有复盘模板成为资产候选。资产的适用条件、反例、来源版本、实际证据与淘汰条件必须可核对；私有项目内容不因复盘自动公开。Intake 按当前任务相关性和现有权限读取项目声明的定位，不自动采纳或执行候选。
