# 原生 App 审查：观察、风险与未验证分开

Modified for ForgeFlow on 2026-11-01; adapted from Impeccable audit.native.md at 2f98774f, Copyright 2025 Paul Bakaus, Apache-2.0. 见 [NOTICE](../NOTICE.md)。本参考服务当前ff-review/ff-design，不新增独立评分门禁、命令或自动修复许可。

先确定本轮目标版本、页面/旅程、OS、框架和证据；iOS读ios，Android读android，双端均读。原生源码/实际构建使用原生证据，不调用浏览器检测或上游impeccable detect冒充原生审查。审查与视觉偏好评价分开：品牌字体、自定义主题不是自动缺陷，系统交互/可用性风险需具体定位。

## 五类检查，按实际范围取用

1. 无障碍：名称、角色、状态、读屏顺序、焦点恢复、大字、触控和减少动态效果。缺少实际读屏操作不得写VoiceOver/TalkBack通过。
2. 性能：启动、长列表、图片、主线程/重建风险。源码能发现潜在风险，帧率、卡顿、内存和启动耗时须有设备/构建模式/场景/测量；未测不得给健康总分。
3. 外观与主题：项目语义token、深浅模式、对比/可读性、主题回退。浏览器或设计图仅支持自身范围，不等原生像素结果。
4. 平台交互：系统/边缘返回、safe area与键盘、模态、权限路径。使用两端具体证据，不以“看起来像原生”替代任务成功。
5. 自适应：已支持设备类别、窗口/横竖屏/字号；不能因为未经批准的平板/折叠场景没实现就认定交付失败，但记录潜在扩大范围代价。

同时按 native-app.md 的FF业务恢复清单检查权限拒绝、输入草稿、前后台/录音中断、离线/重复重试中与当前任务相关的部分。

## 最小报告

按用户影响排序，每项写：目标版本/平台 → 画面或文件位置 → 问题/风险 → 影响 → 实际依据 → 建议与最小复验。状态用“已观察问题 / 源码风险 / 待验证 / 不适用”，有测试通过就注明具体路径/设备，不用统一0–4分掩盖缺证据。

列出真实已有效的做法和重要未验证项；缺实机则给待执行步骤，不虚构结果、不让模拟投票代表真人接受。修正需已有实施授权；修后只重验受影响路径并保留原失败记录，不能自动宣称所有平台重新通过。沿用现有ff-review三类审核/ff-prove按需验证，不要求新安装或改权限。
