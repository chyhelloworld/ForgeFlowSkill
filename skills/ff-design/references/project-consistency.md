# 项目一致性与复用执行约定

这是设计和实施时的约定，不是等复盘才检查。只覆盖本轮相关范围；复用现有需求、计划、差异和证据，不增加阶段、门禁、六份报告或默认全仓扫描。没有触及的类别不展开；同版已核实信息可以复用。外部链接或模块说明不能自动授予跨仓复制、删除、发布权限。

## 动手前：定位当前事实

先核对实际工作区和未提交内容，再沿受影响入口、调用链及直接依赖找当前约定。新增组件、业务逻辑或配置前，查同语义实现、已有服务、组件、配置来源和调用者；在现有任务说明中简述找到的位置、直接复用/小幅扩展/保持独立的选择与理由。没找到时说明实际检索范围，不宣称全仓不存在。项目无相应约定时只补本次所需的最小规则，不默认另建组件平台、配置中心或跨项目目录。

## 执行中：六类约束

1. **样式与组件**：使用已有组件、样式变量和交互约定；必要的小幅扩展放在负责该能力的位置。业务局部例外说明原因，不以统一风格为由重做无关页面。界面变化须核对真实渲染和操作，未观察就标未验证。
2. **配置与常量**：先确认现有配置来源及其所有者。环境差异或确需业务调整的参数接入合适的现有配置位置，避免散落多份值；固定且局部的领域常量可以保留，不把所有字面量配置化，不引入第二套配置中心。密钥不写入源码、日志或普通配置文件。
3. **模块复用**：先使用或合理扩展已有能力，不只在相邻文件搜索。复用前核对业务语义、输入输出、状态所有权、信任边界和变化节奏；不能为了共享而绕过既有接口或依赖方向，也不能默认跨项目复制源码。
4. **重复逻辑**：同语义、同责任且变化一致时，优先在适当模块维护一份实现并验证相关调用方。表面相似而业务规则或生命周期不同，可以保持独立并简述原因；不为消灭重复提前抽象，不为未来假设造包装层。
5. **旧实现退役**：替换功能时同步识别旧入口及调用者，决定保留、迁移或退役。需兼容或用途未知时保留并注明原因、退役条件和受影响验证；确认无有效调用及兼容需求后，在本轮授权范围内移除可恢复旧实现并跑相关回归。代码路径不可达不自动证明外部调用者不存在；不得盲删历史防御、用户数据、未提交内容或扩大全仓清理。跨版本迁移只在原计划中记剩余项，不另建退役系统。
6. **现行文档同步**：需求、接口、配置、启动/测试方法改变时，在同一切片更新受影响的现行说明及示例；历史方案明确标为历史/被替代并保留决策依据，不机械删除。代码说明现状，已确认需求说明目标；冲突时查证是实现错误、需求变更或文档过期，不能自动按代码改需求。纯局部内部调整且对文档无影响，不强制新文档。

## 收尾：核实执行结果

已有独立审查复核本轮适用项：实际复用位置、配置来源、调用方回归、旧入口去向和受影响文档，而非只勾六项。复用已有确定性检查，只有真实反复问题且维护收益合理才增加最小检查。找不到、未运行、无法确认分别如实记录；未完成工作留在原任务中，不能把约定存在当执行成功。小任务可在同一说明中一两句交代，无相关代码/界面变更时不重走设计或架构推导。
