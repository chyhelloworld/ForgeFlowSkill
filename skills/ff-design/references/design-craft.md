# 设计工艺与独立检查

Modified for ForgeFlow on 2026-10-14. Adapted from Impeccable (Copyright 2025 Paul Bakaus, Apache-2.0); see ../NOTICE.md and ../LICENSE-IMPECCABLE. This file is an adaptation, not the upstream workflow.

## 先建立整体，再加工局部

- 看现有页面、代码、资产与实际画面。缺少 DESIGN.md 不等于没有视觉系统；局部优化继承现有身份。已授权重设计保留真实内容、功能、约束与品牌承诺，才替换视觉表达。
- 一句核心概念说明本产品为什么需要这个视觉世界。确定首屏焦点、阅读/行动顺序、空间结构、标志性互动、终点和诚实风险。不要用“高级、简洁、惊艳”替代结构判断。
- 由内容与访客任务推导版式和层级，建立字体、色彩、间距、图像与状态的一致语言。候选差别应是整体体验，不只是改颜色。一个视觉世界统领整页，章节可以有节奏变化，但不能各自重开一套系统。
- 真文案与真实内容长度参与设计；占位示例清楚标明，不虚构产品成绩、经历、背书。参考作品的布局原则可研究，资产授权另行确认。
- 字体行长、密度与图像按语言、页面模式和设备调整；Read 优先长文可读和导航，Operate 优先熟悉操作与状态。避免机械应用英文字宽或固定圆角等审美数字。

## 有目的的 animate

- 写四条最小动效意图：唯一焦点、需要解释的连续关系、必要反馈、性能成本。支持性动效只解释反馈、状态或关系；不为每个章节重复添加淡入上移，也不以粒子、视差和循环装饰掩盖内容不足。
- 控制关系必须来自已确认要求。滚动叙事把位置和路径绑定同一进度，不把滚轮偷偷变成自动播放或拖动角色。暂停/停止输入时运动应按已约定行为停住，反向时沿同一路径合理回退；快速滚动不能穿场丢状态。
- 关键边界记录前、中、后，检查角色身份/尺度、脚与台阶接触、相邻路径、镜头和文字出现是否衔接；布局改变、刷新/恢复滚动位置、短长内容不能造成无解释跳位。先修最小跨段样片，再扩充完整场景。
- 优先现有栈的 CSS、Web Animations 或已有动效库。平滑不能只凭用了 transform 判断；布局驱动属性、模糊、滤镜与画布成本需要实际检查。不要为单一效果无故添加依赖。
- 默认内容可见；脚本失败不隐藏文章。尊重 prefers-reduced-motion：用更少、更轻的运动或静态路径保留信息与反馈。角色动画不能成为读取文章、打开项目或到达页尾的唯一入口。
- 验证桌面滚轮、停止、反向、快滚、跨段；键盘与触摸分别验主要路径。实际触摸需真实设备或浏览器的触摸输入接口完成手势；仅触摸标志、窄屏、程序滚动或合成事件不构成手势证据。记录工具、输入方式、版本和局限。

## 实现的工艺底线

把相关检查合并在同一轮实际渲染中：层级与节奏、正文和占位文字对比（普通文字至少 4.5:1、大字 3:1）、真实长文溢出、响应式结构、可见键盘焦点、可理解控件标签、可触达目标、以及适用的加载/空/错误/成功状态。目标平台或正式无障碍标准另有要求时遵从其要求。不要虚构不适用状态来堆检查项。

避免不经思考的同款卡片墙、数字大标题、装饰渐变和所有段落同款入场；它们是需说明用途的模式，不是禁止用户选择的风格。像素小人或几何楼梯与已确认游戏世界一致时可以使用；不是所有 SVG 或系统字体都不合格。功能真实性、对比与可操作性不能被风格豁免。

## 独立 critique 与既有门禁

固定源文件/预览、版本和目标视口，按风险安排独立审核。重大新方向或动态核心等高风险变更，给两个互不接收对方结论的检查者相同用户目标与设计目标；局部小改可复用一位真正独立的审核者，分别给出以下两轴结论，不强制人数或重开已有效的审核：

A：先看同版实际画面；动态为核心时完整操作或完整播放从触发到结束及相关停下/返回，不用相邻帧抽查代替全程。用户提供基准时实际并看其可比较状态，分别判断质量差距与原创性。独立判断设计针对性、整体构图/材质/色彩、层级、可发现性、情绪峰值/收束和操作因果；记录优点、关键问题与画面/状态/时间证据。未观察核心项标证据不足，不能将“有变化且能返回”当作设计无阻断。
B：独立核对实际浏览器输入、布局、对比、焦点、响应式、减少动态效果、主流程和跨段行为。用当前已有获准工具，不依赖 Impeccable detector、engine、hooks、live 或脚本注入。

高风险双检查者模式中，双方完成前不互相灌输发现；局部单审核者先完成设计判断再查看技术检测结果，并如实注明单审核者模式。随后去重合并，保留分歧、严重度、影响、复现、具体修复和复测状态。映射到 ff-review 的三类独立审核：主要流程与核心需求审核、代码规范审核、计划审核。不能用两个设计检查替代任一现有审核，也不能把模拟角色说成真人测试。

没有独立于实现者的执行者时明确降级为实现者自检，独立审核未完成；高风险双检查者模式无法满足时说明独立性局限，不伪称互盲检查已完成；没有浏览器或真实触摸输入时说明相应未验证。不能以代码、截图数量、评分平均值或检测器零发现宣告体验通过。真人审美选择单独保留。

只采与当前风险相关的证据，首次批量检查后按缺陷集中修复，复测受影响路径及必要回归。持续发现问题时停止无关润色、报告阻塞和下一步；不可把固定轮数、时间/成本上限转换成通过条件。
