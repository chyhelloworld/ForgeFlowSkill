# FF-Prove 0.5.0-rc1

只解决当前方向中值得验证的未知，不为已清楚的任务增设门禁。引用同一需求锚点中的原话、已确认目标/约束/成功标准和独立列出的假设，不用自己的改写替代用户意图。验证主要业务旅程中会改变方向的问题，不为资料或纯视觉机械添加负例/测试。

视觉方向探索/审美选择由 ff-design 或既有设计流程承担；Prove 可为其测试真实交互可行性，但实验成功不替用户选风格或批准审美。引用已选可见目标；未选时仅验证不依赖该选择的获准问题。

1. 复用最新已确认目标、原话/来源、非目标、范围及预算。缺的是用户取舍才问；能查代码/文档的事实先查。仅授权讨论、原型或规格时不能自动转实施。
2. 说清本次要回答的问题、什么观察能推翻假设、投入上限和停止条件。优先沿真实入口验证最难一环；按现有授权继续，不重复审批日常步骤。
3. 根据问题只读 [设计与实验](references/design.md) 中相应部分。真实源码缺失时给条件性分析；文件生成、模拟成功、截图存在都不等于实际体验或端到端已验证。
4. 若问题是动态/空间连续性，用已约定的控制方式跑过关键场景边界，观察整个过程；不要以位置数值、帧切换或几张分屏替代连贯体验。普通任务不新增这项。
   给出观察、证据版本/操作/结果、限制与建议。失败或到上限仍未知时停止依赖该结论的工作，提出最小待决定项；能独立推进的获准工作可继续。
5. 方向足够清楚后交出规划输入：验证了什么、限制与剩余未知、对范围/依赖的影响。需拆实施计划时可交 ff-plan，简单修复可直接内联说明下一步。采纳设计与授权实现分开；已有授权覆盖则继续，不在这里另存一份实施计划。

原型明确标为一次性，放获准隔离位置，不默认上生产或增加持久状态。需要保留原型/结论时沿用任务文件与记录授权；ff-grill Mode 0 不自动保存讨论轨迹。若未安装 ff-grill/ff-implement，本技能仍可独立工作，不要求装其他工具。
