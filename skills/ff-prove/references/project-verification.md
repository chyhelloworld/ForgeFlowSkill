# 项目级可重复验证入口

只在现有入口缺失或已证实漂移时使用；复用 README、测试、脚本或已获准任务记录，不要求创建新技能或第二份功能清单。先覆盖本次目标的一条真实用户路径，再随实际任务维护。

最小记录可放在既有说明中：
- 目标/功能与实际入口：运行哪个命令、从哪里操作、验证哪个用户可见结果。
- 前提与就绪：实际版本、所需服务、只读检查端口/进程/认证是否符合预期；不输出凭据，不因检查缺失自动安装或更改设置。启动与外部请求遵守已有授权。
- 驱动与判据：输入、操作、预期结果和可观察失败；编译、mock或HTTP成功不代替完整目标路径。
- 证据：实际运行时间、源码/制品版本、命令、退出码、观察结果及报告位置；未运行的说明标草稿/NOT_RUN。日志与截图放在要清理的临时对象之外，避免清理后证据消失。
- 收尾：只处理本轮实际启动且归属明确的进程/容器/临时资源，按获准范围操作；已有服务、数据卷、共享缓存和他人工作不动。失败、拒绝与未知状态分别保留，不盲重试。
- 维护：入口、启动依赖或行为改动时更新同一映射，只重跑受影响路径；旧版本证据保留历史身份，不改签为新版本。

一个入口可为多条相关路径服务，不为每条用例制造脚本。工具不具备、真实服务不可访问或只跑了替身，报告该层未验证，继续其他独立获准工作。端口可用不等于目标服务就绪；先核对身份，再观察目标行为。

最小填充例（不是执行证据）：在项目现有测试说明新增“库存扣减：启动既有测试库→经真实扣减接口提交并发请求→核对库存及回执→保存版本绑定结果→仅停止本轮启动的测试实例”；未运行前该记录必须保持 NOT_RUN。
