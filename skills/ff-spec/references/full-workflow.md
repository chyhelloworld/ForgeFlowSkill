# ff-spec 0.9.6-handoff.1

读取提炼需求及最新确认来源、现有规格和可核实项目行为；原话按需追溯。保留一个需求锚点，引用而不另造竞争事实库。事实可查先查；确认不足的取舍交 ff-grill 或简短问用户，不让 AI 推断冒充确认。

规格最少表达：要服务谁/什么主任务；已确认行为与范围、非目标；关键约束和接口语义；可观察验收入口、结果及关键不通过条件；来源、版本、假设与未决项。小修可一句行为变化加一个检查点，复杂产品才扩展文档。

验收分别标识：客观产品行为由真实业务操作/测试证明；主观偏好或用户接受由真实用户对明确版本反馈；技能模拟场景仅验证模型本次决策，不能证明产品运行、原生安装或用户已接受。没有证据就保留未验证，不能将测试全绿写成接受。

已有有效规格直接复用；存量代码缺规格时记录实际行为和已知偏差为事实，拟议要求待确认。变化只修受影响行为/范围/约束/验收，保留旧→新、确认来源与失效影响，不重做无关规格。超出已确认目标、预算或权限的取舍需确认。

默认当前对话或已授权规格位置。Grill Mode 0 不借 Spec 保存完整讨论轨迹；工程规格保存须有自身任务授权。输出供 ff-design / ff-prove / ff-plan 使用；不负责票据拆分、实现、独立审核或发布。

## OpenSpec 与 FF 有效性

遵循 [规格生命周期契约](spec-lifecycle.md)。所有 FF 子命令均通过项目本地 `node tools/openspec/ff-spec.mjs` 运行，工作目录为目标项目根；工具不在此相对位置时使用其真实路径，不回退到全局官方 CLI。仅允许 `init --tools none`，不刷新官方工具集成，`update` 拒绝；包名 `@forgeflow/ff-spec`、用户配置/数据命名空间 `ff-spec` 与官方入口分开，项目 `openspec/` 树仍兼容，这不是文件系统安全边界。现行规格只在 openspec/specs；活动 changes 保存差异和回执，Git 保存历史。按稳定 artifact ID、明确路径、排序内容指纹与依赖指纹判断有效性；review 必须绑定目标版本/内容及依赖。文件存在、任务勾选或旧审核均不自动代表 ready。status / instructions apply / validate / archive 共用 FF evaluator；apply 是实施指导，archive 正常路径同步规格并保存历史。不得继续写旧 spec-state.json，不自动导入旧接受或伪造 pass；取消/拒绝只能走显式 disposition+原因+决议引用的关闭路径，保留失败/未完成记录且不合入规格、不制造 pass。三类独立审核、真实主流程、CRAP ≤50（目标约10）、按需 Diagnose/TDD/Handoff 和既有权限边界保持不变。

## 小范围证据补强

规格应区分交付必须项与预期价值：功能验收可证行为正确，不能自动证明节省时间或业务收益。价值假设仅在本任务需要时记录观察对象、窗口和证据来源；缺基线/阈值保留unknown。讨论、澄清问题不构成批准，不把模拟反馈记为真实接受。

## 变更与恢复边界

用户讨论一个想法或追问不创建任务、不改变现行规格。用户明确加入后，先记录原确认来源与影响分析：哪些现行规格条款、计划任务、测试/验收及依赖受影响；只更新受影响部分，旧结论保留为历史或明确废弃，不能用旧版本审核继承通过。当前规格仅在既有OpenSpec现行目录，活动change表达拟变更，历史归档不当现行指令。

## 技术设计与格式契约
技术架构方案先在 ff-grill 确认取舍；必要时 ff-prove 验证未知，再在本职责输出 design.md，说明边界、数据/调用关系、失败语义和验收。ff-design 仅在界面或视觉需要时调用。
OpenSpec 的结构标题仍用 `### Requirement:` / `#### Scenario:`；正文可用中文，但规范性要求正文必须出现独立英文大写 MUST 或 SHALL，例如“系统 MUST 保留旧证据”。仅标题出现关键词、只有“必须”、场景或代码块内出现关键词不能代替正文格式。strict 不放松；中文关键词别名本轮未新增。

## 需求驱动闭环（按当前任务使用）

按总需求→子需求→用户场景/验收→功能模块建立稳定引用；模块明确职责、边界、协作、验收与未知，支持多对多。需要可读取关联时用[嵌入示例](intent-template.md)，不复制规格或另存接受状态。技术设计按已确认/有依据可能/纯假设区分扩展投入。

模块方案输出前短检一次：读者能否直接找到每个模块服务的子需求、验收和当前未知（可引用共享未知及其影响范围），而无需自行补推？缺的补一句或引用；未发现相关未知如实说明，不编问题，不强制新表格或JSON。

具体来源、关联、转向、旧项目与设计协同遵循[需求闭环契约](intent-loop.md)；小改内联，同次任务已读且未变化时复用定位。
