# UML与普通流程：按问题选一种语义

国内常用术语可并列：顺序图/时序图、构件图/组件图。先确定要表达结构、场景交互、生命周期还是动作控制；不把DFD、活动图、状态图和普通流程图混称“流程”。只展开当前图种，未覆盖的细则查所选版本原规范，不凭工具语法猜。

## UML按类检查（国际规范补充，不冒称国标正文已核验）

| 图种/用途 | 检查关系与常错 |
| --- | --- |
| 类/对象：分类器结构或特定实例快照 | 分清类与实例；依赖由使用者指向被依赖者，泛化指向一般分类器，实现关系指向被实现接口；组合菱形在整体端，不能把普通引用或共享产品画成独占组成。关联多重性双向读；实现图选关键属性/操作，不列所有getter。 |
| 顺序：一个场景的参与者消息 | 生命线明确角色/实例，消息对应操作/契约或事件；同步请求、异步消息、回复不同；按需alt/opt/loop。HTTP202是受理回复，不是后台任务完成；异步任务仍须表达消费、结果与失败接收者。概览不冒充方法级实现；并发纵向位置不证明全局全序或精确耗时。 |
| 状态：一个主体的生命周期 | 先定主体，状态不是validate/save等动作步骤。迁移按需event [guard] / effect；守卫何时求值、事件与竞争策略要清楚。完成迁移可能无显式事件，不能机械判错。 |
| 活动：动作及控制/对象流 | decision/merge与fork/join分清；merge不等待并行分支，join用于同步，不能用join等待两个互斥分支。flow final停止一条流，activity final结束整个活动。泳道代表责任，不自动证明线程。 |
| 构件：模块契约 | 提供/需要接口方向分清，谁承诺谁消费；构件、类、制品、实例不同，C4 component不自动等同UML构件。 |
| 部署：制品落点 | 明确环境、节点/执行环境、制品、实例及通信；逻辑服务到数据库连线不等于部署图。现状数量/落点要有部署资料依据。 |
| 用例：外部角色的目标 | 系统边界与参与者明确，关注可观察目标而非页面/函数目录；include/extend/泛化不能只按中文“包含/扩展”猜方向，使用前核对版本定义与条件。 |

需要通信图、包图、组合结构、交互概览、定时图等时，先确定相应问题与所选UML版本，再查规范对应章；不假称本摘要已穷尽全部UML。无法表达符号时注明简化与文字语义或换格式，不标严格UML合规。

正例：付款成功/失败两个互斥分支用merge汇合；需要PDF和审计都完成的并行分支用join。反例：互斥分支用join而永远等不到另一支；仅停止通知支路却画activity final。

## 普通流程图（工程约定）

采用有图例的起止、处理、判断、输入输出与连接符；判断出口标可判定条件，覆盖所选场景；循环明确退出/耗尽后的路径，异常不会无理由消失。跨页连接标识一致，终点可达。不因画了矩形菱形就宣称GB/T1526逐条符合，也不把普通流程图称UML活动图或BPMN。

正例：校验参数→有效？→是继续/否返回原因；重试次数耗尽走失败。反例：判断出口无条件，失败无条件回到请求而声称一定结束。

## 权威分层（核验2026-10-30）

- **国内体系定位**：[《系统架构设计师教程（第2版）》官方目录](https://www.tup.com.cn/booksCenter/bookcatalog?id=09190101)，2022，§5.3结构化/面向对象方法与§7.2架构文档化。仅目录支持方法选型，不拿未读章节作箭头规则依据。
- **国内标准目录已核验**：[GB/T 28174.1～.4-2011官方目录](https://openstd.samr.gov.cn/bzgk/std/std_list?p.p1=0&p.p2=GB%2FT+28174&p.p90=circulation_date&p.p91=desc)，现行推荐性，2012-06-01实施，分别基础结构/上层结构/OCL/图交换。未取得国标正文，不宣称逐条符合；不能把2017年的UML2.5.1当作2011国标相同版本。
- **国际规范补充**：[OMG UML2.5.1](https://www.omg.org/spec/UML/2.5.1)，2017-12，[全文](https://www.omg.org/spec/UML/2.5.1/PDF)。已核验§7.7依赖、§9分类器、§11.5/11.6/11.8类/构件/关联、§14状态、§15活动、§17交互、§19部署；表格为短摘要及FF应用，不复制原表。严格国标任务仍需对应国标正文，不能以此替代认证。
- **流程国标仅题录**：[GB/T1526-1989公开系统](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=D19A1DF7C8A8058E26EC8DFE9EBD001B)，现行，等同ISO5807:1985；未核正文，以上为工程检查约定，不虚报条款号。Mermaid/PlantUML/draw.io只是表达/渲染工具，版本语法另查工具官方文档，不作为模型语义权威。
