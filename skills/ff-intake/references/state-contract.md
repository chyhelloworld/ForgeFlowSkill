# 轻量状态与证据契约

只复用项目已有权威载体；非规格产物复用既有位置；启用 OpenSpec FF 时，现行规格固定为 openspec/specs，策略使用稳定 ID 显式映射路径，不建立第二套数据库或常驻调度器。每份必要产物可为一段内联文字。引用原话/确认来源与版本，事实、假设、用户选择分别列明。

- Spec：已确认行为、范围/非目标、约束、可观察验收；不得将逆向代码行为自动视作承诺。
- Plan：映射 Spec 的纵向切片、边界、真实依赖、验收与当前状态；ready 只是技术可开始，不授予实施权限。
- Evidence：对应 commit/快照、环境、实际操作/原始输出与覆盖范围。状态 PASS、FAIL、NOT_RUN、BLOCKED、有理由的 N/A；指标缺数据用 NOT_MEASURED。
- Review：plan、goal-mainflow、code 各有独立结论，来源为真正独立上下文；无独立上下文标独立性未满足。
- Acceptance：用户对明确版本与范围的反馈。测试通过、技术交付、技能模拟评估与真实用户接受分别记录。

恢复时查目标/权限、工作区含未跟踪文件、环境、旧命令可观察状态及部分产物；不可查询标 unknown，不凭时间判断、不杀他人进程、不重复可能写入的未知操作。保护他人修改。

变化链：最新明确采纳来源 → 受影响目标/生产者/消费者/切片 → 失效的规格、任务、测试、审核和用户接受 → 最小修订与复验 → 可保持的无关结果。讨论可能性不等于采纳。Intake 只给对账结果；Spec、Plan、Implement 更新各自已有获准载体，Review 独立复核，Deliver 交接有效证据。新版本不能自动继承旧版本用户接受；无关证据可保留但说明适用范围。
