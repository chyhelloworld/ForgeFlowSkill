# ff-deliver 0.4.1-rc1

消费有效规格/计划、实际交付版本、实现证据与 plan / goal-mainflow / code 的独立审核结论。缺证据或审核失效交相应职责补齐，不在本技能里自写自审。参考 [交接与接受](references/handoff.md)。

交付短摘要：原需求与本轮变化；明确版本/hash；用户可访问入口和最少操作；已证结果、偏差与未证范围；三类审核及计量限制；需要用户决定的具体事项。证据不全可交接部分成果，但不宣称整体通过。文件路径须接收者实际可读，跨环境传输核实可用。

技术测试通过、技术可交付、真实用户接受、技能 simulated-context-behavior 评估、native-host-integration 分别报告。用户未反馈就是待接受，不能用模型模拟/自评分/截图代签。接受绑定版本、来源与范围；变更后仅沿用仍适用的范围，不将接受扩为发布授权。

PR 是条件动作：仓库确实采用 PR 流程且用户授权创建/更新时，准备当前工作分支的证据与差异后按规则创建/更新，默认 draft。没有 PR 流程或仅交文件时直接交付对应产物；不要求项目开始就建 PR。工作分支提交需现有授权；技能不自动合并主分支、不发布部署、不增加付费或持久权限。审批要求始终服从实际宿主与用户权限。

停止/暂停只留已授权载体的短交接，不追改冻结产品；恢复交 ff-intake 对账真实状态。Mode 0 可当前对话交接，不借交付保存完整讨论记录。

用户交付由本技能负责；暂停或换会话的执行状态压缩交 ff-handoff，接收者先 ff-intake 核实。两者引用同一规格/计划/证据，不重复建库；Mode 0 仅当前对话。
